Drex 深读：决策模型作为自回归推理的生产级替代

自回归长思维链在定义良好的决策任务上精度高但生产代价大（答案不稳定、要解析输出、贵且慢），Drex 用四个开源决策模型证明另一条路：给定状态+问题+选项集合，模型单次前向直接输出选项上的概率分布——无解码、天然合法输出、可校准。旗舰 Drex Max（Qwen3.8-27B 密集多模态、每四层一层非因果全注意、255 码读出头）在 Decision Index 0.4.1 公榜 67.52 创决策模型新 SOTA（对 Jev 1.14.0 +6.8）、183ms 中位延迟（GPT-6 Sol 约 2.0s）、每千次决策 $0.06（Opus 5.5 的 1/170）；训练靠 SFT+一致性正则 → RLAF（验证结果+同基座裁判的 KL 正则奖励）→ 视觉 SFT 三段，消融显示 RLAF +2.0 分、一致性项把翻转率 6.3%→4.2%。

01 / 靶子：自回归推理的生产税

论文开篇把行业默认架构的成本摊开：长思维链推理精度高，但生产环境付三重税——答案不稳定（同一问两次跑可能不同）、要解析输出（自由文本→结构化决策的转换层）、贵且慢（Table 8：GPT-6 Sol 中位约 2.0s/请求、3.33每千次决策；ClaudeOpus5.5约3.5s、3.33 每千次决策；Claude Opus 5.5 约 3.5s、3.33每千次决策；ClaudeOpus5.5约3.5s、10.17）。决策模型（decision model）走判别式路线：输入「状态（文档/记录/agent 上下文，可带图像）+ 问题 + 选项集合」，输出选项上的概率分布——无自回归解码、输出天然合法（支撑集恰为所给选项）、概率可直接用于路由与审计。接口沿用 Jev 的 System One 与开源 Kev 栈，Drex 的贡献是把它做到开源前沿并系统回答四个 RQ：校准、选项顺序稳健性、训练配方贡献、架构取舍。

生产税的三个面孔各值多少

把三重税分开估价（本页整理，依据全文数字）：不稳定性税——§12 测得随机换序翻转率 4.3-5.9%，而自回归模型同题重跑的方差还要叠加采样温度；对接阈值路由的系统，一次翻转就是一次行为变更。解析税——生成式输出需要「提取答案→校验格式→失败重试」的转换层，这层代码在生产事故清单上常年霸榜；决策模型的输出即结构化分布，转换层归零。延迟与成本税——Table 8 的量级差是 11 倍延迟（183ms vs 2.0s）、55-170 倍价格（0.06vs0.06 vs0.06vs3.33/$10.17 每千次）。三者可加起来读：如果 Agent 的每个工具选择、每次终止判断、每条结果审计都从「调用一次对话模型」换成「调用一次决策模型」，系统级行为会从「偶尔卡住/偶尔答非所问/月底账单惊人」变成「稳定/结构化/便宜到可以随处放」——这是决策模型作为基座能力（foundation）的含义：不是替代对话模型，而是把系统里 80% 的微决策卸载到一条快车道上。

为什么「输出形状」是第一性问题

引言对读出方案的谱系梳理值得慢读：分类头（标签训练时定死）、T5 式文本到文本、解码器提示生成、约束解码（限定生成串并按逐 token 概率乘积归一——但选项共享前缀或长度不齐时该值≠模型对整串的分布）、逐选项打分再归一（每选项一次前向）。这些方案的共同缺口：候选集合在推理时由用户给定时，没有一个原生输出「集合上的分布」。决策模型补的就是这块——选项数 3 或 150 用同一个头，训练没见过的选项照样打分。这个定位决定了适用边界（§16 展开）：凡能写成「从给定选项里选」的任务（分类、是非、评分、重排、路由、agent 内判断）都适配；需要生成开放文本的任务不在射程内。

03 / 指针架构：状态编码一次，问题各自打分

请求打包成「状态段 + 每问题一块」的 token 序列，块因果掩码让每问只注意状态与自身块；混合底座（Gated DeltaNet 层不能用任意掩码）则改为「状态缓存 + 每问独立因果序列」，位置编码让每问在坐标上都紧跟状态尾——问题独立性由构造保持（细节见下节）。指针头极简（Eq.2）：

为什么问题独立性能由构造保证

这块值得慢讲，因为它是「概率可复现、可缓存、可审计」三件套的架构根基。纯注意底座（DLM）上用块因果掩码：问题块的 token 看得到状态段、看得到自己块内前文、看不到任何别的问题块——第 5 个问题的答案不因前 4 个问题是否存在而变，数学上 pkp_kpk​ 只依赖 (S,bk)(S, b_k)(S,bk​)。混合底座（DeltaNet 循环层无法施加任意掩码）的替代方案更巧：每问作为独立因果序列跑（状态+该问），状态编码缓存复用；位置编码重置让每问的第 j 个 token 的位置号都等于「状态尾 + j」——于是无论这问是单独来、跟一批问一起来、还是从缓存重放，模型看到的坐标完全一致，输出在浮点误差内恒等。附录 C.2 还给出可选的「选项隔离掩码」让注意底座上的指针头对选项置换等变（架构级顺序稳健），但混合底座用不了——这就是顺序稳健性只能「学」的架构原因，也解释了为什么一致性正则（§05）存在。

指针头的经济学：参数、缓存与 21.6ms

指针头的成本结构值得记三个数：参数近零（2.1M/9B 的 0.023%）——全部决策能力住在 backbone 的表示里，头只是读出接口；状态缓存是复利——114-117k token 的状态编码一次后，每追加一问只付 21.6ms（比 2k 新上下文的状态段 35.6ms 还快），多问长文场景的边际成本趋近于零；最坏情况有上限披露——131,072 token 全长状态段约 2.7s，超出自设 2s 目标（论文如实报，不藏）。这三个数合起来是「什么时候选指针系」的完整答案：状态长、问题多、成本敏感时，指针模型的架构红利最大；反过来——每问独立、状态短、精度优先的部署——Max 的读出头与双向注意赢面更大，两系共享同一接口意味着可以在同一系统里按请求特征混布路由——长文多问走指针系、单问短文走 Max，这是同一 API 下的零成本切换。

两种头的本质差异：选项表示在哪里生成

ECE（期望校准误差）的算法值得展开一遍（教学重演，论文用 15 等宽桶）：把决策按预测置信度分桶，每桶算「平均置信 − 实际准确率」的绝对差，再按桶内样本数加权平均：

12 / 顺序稳健性：翻转率的显微镜

1,591 个决策（915 二选、503 三至五选、173 六选以上）× 三种顺序（原序/逆序/随机置换）：Max 翻转率 4.3% [3.3, 5.3]、v2.0 5.9%、v1.5 5.3%、Jev 4.3%——读出头的 Max 与指针架构的 Jev 打平、反超自家指针（一致性正则的功劳，§13 消融）。三个更深的事实：其一，翻转不伤精度——三序准确率极差 ≤1.2pp（Max 83.6/83.3/83.4），翻转在增益与损失间近乎对消。其二，翻转与低置信高度重合——翻转样本准确率仅 37.6%（稳定样本 87.2%）；按「不稳定即弃答」弃答与按等量最低置信弃答，留下的决策精度几乎一样（87.2% vs 87.1%）——低置信已经预警了不稳定性，用户盯置信度就够了，不需要在生产里额外跑三序一致性检查。其三，选项数主导翻转率——二选 1.0%，六选以上 13-16%（所有模型皆然）：多选项时头部概率近平局，换序换头不出奇。三序平均的 ensemble 降 log loss（Max −0.014 nats 显著）但不涨精度。教学手算（近平局翻转）：(0.51,0.49)(0.51,0.49)(0.51,0.49) 置信 c=(0.51−0.5)/0.5=0.02c=(0.51-0.5)/0.5=0.02c=(0.51−0.5)/0.5=0.02——置信度近乎零的决策换序翻转毫不意外；(0.9,0.1)(0.9,0.1)(0.9,0.1) 的 c=0.8c=0.8c=0.8 则几乎不可能翻——这就是「翻转⊂低置信」的机制。给生产者的操作翻译：置信阈值 0.5 以上的子流里，翻转率将远低于总体的 4.3%（大部分翻转样本已被阈值滤除），不必为顺序稳定性单独设计防护或检测。

14 / 部署工程：无解码循环的服务账本

§9 是决策模型工程学的浓缩。两段前向：状态段一次（成本随上下文长）、问题段每问一次（极短）；上下文缓存后每问 21.6ms（114-117k token 已编码），比 2k 新上下文的状态段（35.6ms）还快——多问长文场景状态段主导。131,072 token 全长状态段约 2.7s，超他们 2s 最坏目标（如实报）。三项优化：共享 prefill（同请求多问共享状态编码，8k 上下文 16 问提速 6-8×、32k 提速 11-12×，输出位级一致；<1,024 token 反而变慢故不启用）；CUDA Graphs（1k token 单问延迟砍约 2/3，6-8k 后收益消失）；核替换（逐项验证「概率位移在容差内且无决策翻转」才接受——这套验收抓住了 packed-prefill 的一个真 bug：输出合法但答案错，延迟测量永远看不见）。Max 因不共享缓存走另一路：Blackwell 核级优化。答案变更型优化的精度账（Table 9）：FP8 vs bf16 零损失；图填充+小批 FP8 −0.34pp（超阈值被权衡接受）；每项改动都有配对 bootstrap 区间——「优化必须过评测关」是本文工程部分的职业道德亮点。

共享 prefill 提速的算术与 CUDA Graphs 的适用边界

共享 prefill 的提速倍数可以手算核验（教学重算）：16 问×8k 上下文，无共享时每问都付 8k 状态段 = 16 次 8k prefill；共享后 1 次 8k + 16 次短问题段。状态段成本 ∝ 长度，问题段约 100-200 token——省下 15 次 8k prefill，总计算量从 16×8k+ 降到 8k+16×0.15k，比值约 128k/10.4k≈12×，与论文「8k 处 6-8×、32k 处 11-12×」的量级吻合（问题占比越大提速越低，故 8k 处倍数反而小些的细节由注意力的二次项修正）。CUDA Graphs 的边界同理可推：kernel 启动开销约固定（数千个小核 × 微秒级），计算时间 ∝ token 数——1k token 时启动占比主导（砍 2/3 有效），6-8k 时计算追上启动（收益归零）。这两条边界对自部署者的启示：优化选项由「请求形态分布」决定——短问高频选 Graphs、多问长文选共享 prefill、两者都有各自的失效区，盲目叠加会互相抵消（论文在 <1k 上下文关闭共享 prefill 正是此理）。

「按请求重采样」为什么不是小事

统计单元的选择直接影响显著性结论（教学整理）：DI 一个请求含多问（同状态），同一请求内的决策正相关（状态难则全难）——若按决策独立重采样，有效样本量被高估、置信区间偏窄、差异容易被误判显著。教学手算：100 个请求×10 问=1,000 决策，请求内相关系数 0.3——独立假设计的方差低估约 1+(10−1)×0.3=3.71+(10-1)\times0.3=3.71+(10−1)×0.3=3.7 倍，标准误低估约 3.7≈1.9\sqrt{3.7}\approx1.93.7​≈1.9 倍，p 值会被大幅压小。Drex 按请求重采样把单元选对；同理 DI 分数区间按基准重采样回答的也是「基准集选择」这个更高层的随机性。这套协议值得任何做 agent 评测的人照抄——agent 任务天然「一个 episode 多个判断」，统计单元错置是这类评测最常见的隐性通胀。

16 / 边界、适用判据与定位

论文的局限节（§10）与全文证据合起来可以写成一页部署判据。哪里该用决策模型：选项集合可枚举（分类/是非/评分/重排/路由/agent 内判断如工具选择、终止判定、结果审计）；概率要接阈值做路由或人审；延迟预算在几百毫秒级；成本敏感（0.06vs0.06 vs0.06vs3.33-10.17 每千次，量级 55-170 倍）。哪里不该用：闭卷知识密集（HLE 16 vs 70——论文建议路由到别的系统）；长结构序列选项（和弦/偏好档案，读出头绑定弱，55.6/50.5）；开放文本生成；需要跨问题共享超长状态且成本优先时选指针系而非 Max。证据强度分层：DI/Decision Bench 为自家跑分（协议严、与官方榜差 ≤0.8）；AA 榜为第三方（无区间）；v2.0 阶段贡献为串联观察；Max 的架构归因（读出头 vs 非因果掩码 vs 27B 密集底座）未做受控分解——论文明列在未做实验清单里。定位：Drex 是「决策模型作为基座能力」路线目前最完整的开源参考实现——接口沿 Jev、代码沿 Kev、注意力与读出沿 pplx-decider，训练配方（一致性正则+RLAF+视觉段）与评测纪律是增量贡献。放在本周的语境里：它与 Rethinking Agentic RL 互为镜像——那篇证明 agentic RL 的增益藏在错误恢复，这篇证明很多「推理」任务根本不需要恢复能力，一次前向的判别就够；两者的分界线（任务能否写成给定选项上的选择）本身就是 2026 年 agent 架构设计最有用的一道预筛。

agent 系统里的具体卸载点（本页整理）

把判据落到 agent 架构（与本周 Claude subagents 文的接口呼应）：(1) 工具路由——MCP 工具一多，选哪个工具是「N 选项分类」，Decision Index 的 Tools 域 skill 81.9 正对此景；(2) 子代理结果审计——Claude 文的「真数据验证」环节，用决策模型判「子代理断言与检索证据是否一致」（noul 型）比再调一次生成模型便宜两个量级；(3) 终止判定——agent 该停了吗，是「继续/停/换路」三选；(4) 重排与筛选——检索候选、skill 选择、内存条目都是重排任务。四个卸载点的共同形状：高频、小决策、选项可枚举——正是 Table 8 价格差被调用量放大的地方。反向清单同样具体：需要写代码/写长文/开放规划的环节留在生成模型；闭卷事实问答路由到 RAG 或大模型；音乐/结构化序列预测这类「选项本身是复杂对象」的任务目前两头不讨好。

开放问题：这条路线的下一程

论文未做实验清单加上本页的阅读，可以列出四个最有价值的下一步：(1) 架构受控分解——同 27B 底座上指针头×读出头×因果×非因果的 2×2 消融，把 Max 的 6.3 分增益拆到组件；(2) 裁判覆盖的实测频率——§07 手算显示需要 55 倍概率比才翻转，但训练分布里的实际发生率未测，这是 RLAF 安全性的关键缺口；(3) 温度的在线自适应——静态全局温度在跨域部署时失效（§09 的逐域 ECE 证据），按请求特征动态调温或分域温度表是显然的改进方向；(4) 决策模型与生成模型的级联——HLE 16 vs 70 的鸿沟暗示混合架构（决策模型筛选项、生成模型深答前二）可能兼得成本与精度，论文只提了路由思路没做实验。这四条也标记着「决策模型基座化」从技术报告走向成熟产品的距离。

理解自测

六个检验接口理解与数字解读的问题

  1. 置信度手算：四选项分布 (0.55, 0.20, 0.15, 0.10) 的 c_choice 是多少？noul 问题 p(yes)=0.93 的置信度又是多少？

    c=(max p − 1/K)/(1 − 1/K)。

    展开参考答案

    四选项：c=(0.55−0.25)/(1−0.25)=0.30/0.75=0.40。noul（K=2）：c=(0.93−0.5)/0.5=0.86。注意同一 max 概率下 K 越大置信越高（0.93 在二选时 c=0.86，在四选 c=(0.93−0.25)/0.75≈0.91）——归一化把「随机猜对的先验」扣掉了，跨 K 比较置信度才有共同标尺。

    §3 Eq.1；手算见 §02

  2. Cramér 距离手算：五等级目标 y=5，预测 p_a=(0,0,0,0.2,0.8)（近错）与 p_b=(0.8,0,0,0,0.2)（远错）的 D_C² 各多少？比值说明什么？

    D_C²=(1/(K−1))Σ_i(Σ_{j≤i}p_j − 1[i≥y])²。

    展开参考答案

    p_a 累计 (0,0,0,0.2,1)，偏差 (0,0,0,0.2,0)，D_C²=0.04/4=0.01。p_b 累计 (0.8,0.8,0.8,0.8,1)，偏差 (0.8,0.8,0.8,0.8,0)，D_C²=4×0.64/4=0.64。比值 64 倍——同样是 20% 质量放错位置，错到远端等级的罚是近错的 64 倍；这就是 score 问题用 Cramér 而非纯交叉熵的原因：它把「错误的距离」写进损失。

    §6.2 Eq.7；手算见 §05

  3. 温度方向判断：某部署里模型均值置信 95%、实际准确率 88%。T⋆ 应大于还是小于 1？调温后 argmax 会变吗？

    T>1 平滑、降信心；同除正数保序。

    展开参考答案

    过信（95>88）→ 需要 T⋆>1 把分布拉平、信心降下来。argmax 不变：所有 logit 同除 T>0 保序，温度只重标置信度不改决策——所以调温能修 ECE 但一分精度都不动（Table 4 中 Max 准确率 87.9% 在两个温度下相同）。反向情形（欠信）则 T⋆<1 锐化，如 v2.0 的 0.91。

    §6.6 Eq.14、§8.4；手算见 §09

  4. 「Drex Max 183ms 对 GPT-6 Sol 约 2.0s，快 11 倍」——这个对比公平吗？哪些前提该被指出？

    看 Table 2/8 的任务构成与模型职责差异。

    展开参考答案

    三点前提：其一，比的是决策请求（状态+选项）而非开放生成——GPT-6 Sol 在做的是先长推理再答题，把推理算力花在 Max 不花的闭卷知识上；其二，Max 的 183ms 是中位且含 70-215ms 网络时间（自测披露），131k token 最坏状态段 2.7s 超其自定 2s 目标；其三，精度上 Decision Bench 94.0 vs 94.7 统计不可分，但 HLE/GPQA 差距巨大——公平的表述是「在定义良好选项集的任务上以 1/55 成本换统计等价精度」，而非全面 11 倍加速。

    Table 8、§8.2、§9.2；解读见 §11、§16

  5. 翻转率 4.3% 与低置信的关系：若一应用按置信度 0.5 阈值弃答，还会看到多少翻转？依据 Table 5/20 的证据怎么推理？

    翻转样本准确率仅 37.6%，稳定样本 87.2%；二选翻转率 1.0%。

    展开参考答案

    证据链：翻转集中于低置信与多选项（K≥6 翻转 13.3%、二选仅 1.0%）；近平局分布（如 0.51/0.49，c=0.02）几乎必然低于 0.5 阈值——所以按 0.5 弃答后剩余决策的翻转率会远低于总体的 4.3%（大部分翻转样本已被阈值滤掉）。论文的直接证据：按「不稳定即弃答」与按等量「最低置信弃答」的剩余精度几乎相同（87.2 vs 87.1）——两者筛选的几乎是同一批样本。

    §8.5、Table 5/20；手算见 §12

  6. Max 全分 66.60 只比公榜低 0.9，v2.0 却低 8.5——这个分化说明什么？不能说明什么？

    全分=公榜+私测（同技能+新域）。

    展开参考答案

    说明：Max 的新域/私测泛化与其公榜表现一致（新域 56.45 vs v2.0 的 39.22），27B 密集+非因果注意+更大数据的组合在分布外放大优势——这对「买榜单还是买能力」的判断是强信号。不能说明：私测具体内容不可见，无法排除「Max 的训练分布恰与私测新域更近」的替代解释；且 v2.0 与 Max 差四个变量（规模/注意/头/数据），分化无法归因到单一原因——论文自己把架构归因列为未做实验。

    §8.1、Table 1；解读见 §08、§16
