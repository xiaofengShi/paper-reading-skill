Start a new agent session and paste:

Use $paper-reading to explain https://arxiv.org/abs/2106.09685v2 in English.
I know basic neural networks but am new to LoRA. Explain why it saves
trainable parameters, work through a small example, and distinguish
reported results from interpretation. Save the offline HTML and Markdown

Expect paper-readings/lora/reading.html and its Markdown audit source after the agent completes the reading. The agent reads and authors the explanation; the renderer turns that Markdown into HTML. The skill is free and needs no separate API key; your agent's normal model access and charges still apply. Other agents, installation options, and troubleshooting.

What you get

  1. Whole-paper map The question, setting, proposed idea, contributions, and where evidence enters.
  2. Method or argument path Inputs, stages, branches, feedback, and outputs, with consequential arrows explained.
  3. Mechanism close-ups Definitions, equations, assumptions, and a worked example where it helps.
  4. Experiment atlas Each question linked to its setup, comparator, metric, observed result, and supported reading.
  5. Connected synthesis What the method and evidence show together, with limits attached to the affected claims.
  6. Understanding checks Paper-specific questions about a mechanism, small application, or evidence boundary, with answers you reveal when ready. These are learning aids, not a measured comprehension score.

The diagrams guide reading; prose, formulas, tables, and original figures carry the detail. Source locations stay available for verification but are hidden by default in the HTML. The output is one offline-readable file, with Markdown as its audit source.

The reading method

The workflow combines established reading and knowledge-mapping ideas with a paper-specific editorial design. Its three checks answer different questions:

  1. Can we reconstruct the paper before explaining it Keshav's three-pass approach moves from an overview to the paper's content and then to a detailed reconstruction. The skill uses the first pass to draft a provisional map, the second to follow methods and results, and the third to work through the decisive equations, assumptions, proofs, or experiments. A normal deep-read request completes the full route; a quick scan is a separate user choice.
  2. Does each diagram express a meaningful relationship Novak and Cañas's concept-map method starts with a focus question and connects concepts with labeled relationships and cross-links. Here, a map answers a paper-specific question such as “How does the mechanism change the result?” Arrows say whether they mean data flow, process order, or evidence; the accompanying text explains what they connect.
  3. Can a reader check the explanation against the paper SciDoc2Diagrammer-MAF reports that generated scientific diagrams can be incomplete or unfaithful to their source. This project takes that as a fidelity check: significant figures, formulas, numbers, and arrows must be checked against the source, and each experiment is read with its setup, comparator, metric, and result. It does not implement that paper's diagram-generation algorithm.

These ideas guide five explanatory layers: global map, main path, mechanism, experiment atlas, and synthesis. The understanding checks supplement the explanation when useful. The test of a useful deep read is whether someone can explain the paper's central mechanism and say which evidence supports each important claim, without hunting through the PDF for missing essentials. This is the project's method design, not a claim that the published examples have been validated in a reader study.

The public reading-quality checks turn that intent into release gates for source coverage, scientific fidelity, claim-to-evidence links, reader completeness, and offline delivery. The reader tasks and answer keys make every published example testable by someone who did not write them. A renderer test or an author reviewing their own page is not an independent comprehension study.

Get started

The quickstart above installs a project-local Codex copy using the skills CLI. The bundled renderer needs Node.js 20 or newer. Your agent also needs access to the complete paper and tools to read it.

Personal installation and other agents

Choose an unused personal skill directory:

Agent Personal directory Explicit invocation
Codex ~/.agents/skills/paper-reading $paper-reading
Kimi Code ~/.agents/skills/paper-reading /skill:paper-reading
Claude Code ~/.claude/skills/paper-reading /paper-reading

For Codex or Kimi Code, clone the repository as follows. For Claude Code, change the first line to paper_reading_dir="$HOME/.claude/skills/paper-reading".

paper_reading_dir="$HOME/.agents/skills/paper-reading"
mkdir -p "$(dirname "$paper_reading_dir")"
git clone https://github.com/xiaofengShi/paper-reading-skill.git "$paper_reading_dir"
(cd "$paper_reading_dir" && npm ci && npm run doctor)

doctor renders a small, explicitly synthetic fixture in a temporary directory and checks language, navigation, embedded math fonts, an SVG, and a chart. It does not download or read a paper, and passing it does not verify scientific content.

Start a new agent session, attach a PDF or give an accessible paper URL, and ask: “Read this paper deeply in English. Give me one visual HTML reading document that explains the main path, important equations, and experiments.” Replace “in English” with your preferred language. With no language cue, the skill defaults to English; a request in Chinese produces Chinese output. The native renderer provides English and Chinese navigation.

For an existing Git clone, review local changes, run git -C "$paper_reading_dir" pull --ff-only, then rerun npm ci and npm run doctor there. CLI-installed copies and lightweight packages may have no Git history: preserve local changes before replacing them with a fresh installation.

Start a reading directory

An optional initializer creates a place to work. From a project with the quickstart installation:

node .agents/skills/paper-reading/scripts/init-reading.cjs \
  --out paper-readings/my-paper --title "My paper" \
  --paper "https://arxiv.org/abs/2106.09685v2" --lang en

This creates reading.md, brief.md, and an assets/ directory. The Markdown is visibly marked unfinished. The command does not fetch the paper, write a deep read, or generate HTML; the agent must complete and check the draft before rendering. An existing destination is refused. Use --lang zh-CN for a Chinese draft, or run npm run init:reading -- --help inside the installed skill for all options.

Build a lightweight local package

To install without the public gallery and website, download paper-reading.tar.gz from the v0.2.0 release, or build a runtime package from a repository checkout:

npm ci
npm run pack:skill

The result is dist/paper-reading/, including a SHA-256 manifest.json, and dist/paper-reading.tar.gz when the system tar command is available. Copy the whole runtime directory to an unused skill location from the table, then run npm ci and npm run doctor inside that copy. It includes the renderer, helpers, references, and synthetic check fixture; it excludes docs/, examples/, dependencies, and tests. Existing package outputs are refused; use npm run pack:skill -- --out <new-output-parent> for another build.

Troubleshooting

Symptom What to check
Missing marked or katex Run npm ci inside the installed skill, with its package-lock.json present.
Missing helper or fixture files Install the full checkout or generated runtime directory; copying SKILL.md alone is insufficient.
ERR_REQUIRE_ESM with an older installation Update the skill and reinstall its dependencies. The current renderer supports Node.js 20.18 and newer.
Agent cannot find the skill Confirm its installation directory and start a new session; use the explicit invocation above.
Initializer says the destination exists Choose a new reading directory; the initializer preserves existing files.
Agent only has an abstract or inaccessible PDF Provide the full source or keep the result explicitly incomplete. A summary cannot stand in for a complete deep read.

The agent performs the scientific reading and authors the Markdown; the renderer converts that Markdown to HTML. Ask for a quick scan when you want triage, or a review or research comparison for those additional lenses. An ordinary request stays understanding-first.

How it works

The skill instructions guide an agent through orientation, full reconstruction, explanation, and source checking. Paper-type routes select suitable views for empirical, systems, benchmark, dataset, theory, and survey papers; visual-reading rules keep diagrams tied to explanations and evidence. Reading modes define the optional scan, review, and research lenses.

The bundled renderer turns a Markdown audit source and local visuals into a standalone HTML file with embedded images, diagrams, KaTeX math, and fonts. Every source begins with an explicit language marker, <!-- paper-reading-lang: en --> or <!-- paper-reading-lang: zh-CN -->, which sets navigation and chart labels. An optional second line chooses one of four built-in visual themes: <!-- paper-reading-theme: forest -->, cobalt, plum, or saffron; the default is forest. The author selects a theme for each paper rather than having the renderer guess from its text.

For each paper, the skill judges whether exploring a branch, state change, or feedback loop adds understanding; otherwise it uses a static view. An interactive view can use Archify or self-contained HTML/SVG, with the key explanation still visible without scripts. Neither Archify nor another locally installed skill is required. The renderer input format documents the Markdown contract, figure extraction covers original figures, and understanding checks describe focused questions with native answer disclosures.

The ResNet, LoRA, Transformer, DeepSeek, MiMo, RAFT, MechVQA, IAR, VISTA, OpenDS-World, and OmniDR-Bench Markdown sources and visual inputs are build materials, not separate reading pages.

npm ci
npm run doctor
npm run build:examples

Validation and scope

Different checks support different claims:

Check What it can establish Boundary
Automated structure and rendering checks Input contracts, language and theme declarations, math, declared embedded assets, chart behavior, and generated-file freshness. A passing renderer cannot establish scientific correctness or reader understanding. The doctor uses synthetic material.
AI-assisted source checks Trace an explanation's equations, figures, numbers, and claims to an identified paper version; record discrepancies and missing coverage. Report what was checked and what remains uncertain. These checks are not experimental reproduction or independent human review.
Independent reader evaluation The reader tasks provide questions and answer keys for a future evaluation. No independent reader study has been reported. Answer disclosures and AI answers are not evidence of measured human learning.

The gallery covers architecture, parameter-efficient adaptation, technical reports, domain fine-tuning, engineering benchmarks, document knowledge internalization, and agent harnesses. Theory and surveys remain outside the current example set. LoRA's small matrix and parameter-count exercises are labeled teaching examples, separate from the paper's reported experiments. The project has not established that its format improves comprehension over other reading methods.

Archify is an optional presentation tool for interactive structure diagrams. Scientific fidelity still depends on reading and checking the source paper.

Questions, bug reports, and examples from other paper types are welcome in GitHub Issues. The project is MIT licensed.
