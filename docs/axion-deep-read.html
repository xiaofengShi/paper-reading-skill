01 / 靶子：训练管线的复杂度惯性

论文开篇的诊断不是「现有模型不够强」而是「现有配方不够懂」：现代 agent 模型的训练栈普遍是中途训练 + 多个监督阶段 + 能力专属数据配比 + 偏好优化 + RL + 各种附加后训练的叠加。每个成分单独看都有动机，但叠起来之后就没人说得清哪些是必要的——复现成本抬高、能力增益的来源被淹没、配方换一个基座就失灵。第二个靶子是「假开源」：很多模型放权重，但数据构造、过滤、验证、prompt、训练过程全部缺席——而 agent 基座的能力恰恰取决于数据和交互设计，不只是一个权重文件。Axion 的回应是一句问话式的宣言：训练管线可以简化到什么程度，还能造出强而广的 agent 基座？ 边界句要立刻钉住：「简化」指训练阶段结构（不做中途训练/DPO/OPD），不指数据构造工作量——恰恰相反，论文的原则是「简化训练管线不需要简化学习问题」，把力气全花在题目质量上。这个立场后面每个数字都要靠它解释：18.3K 道题训出 HLE 59.0（受限口径），靠的不是量大是题难且可验证。

为什么「过程件开源」比权重开源难得多

权重是一个静态制品，放出即完事；过程件是一个决策链——种子从哪来、难化算子怎么选、验证失败率多少、哪些题被闭书探测剔除、RL 任务池过滤后剩多少，每一环都有参数与判断。放过程件等于把这套判断链摊开接受检验：别人可以逐环复算、逐环挑错，也可以换掉任何一环看后果。论文相关工作里点名了这条路的上游：OpenThoughts 开推理数据配方、OpenThoughts-Agent 开 agentic 数据管理、DR Tulu 开 RL 框架、QUEST 开模型+数据+脚本——Axion 把它们拼成一条从种子到 RL 的单一连续管线并保证每一环的开源粒度对齐（能跑、能改、能对账）。这个背景下再读「简单配方」的动机会更准：管线越短，过程件越可检查——三段式不只是省算力，也是让开源承诺可兑现的结构性条件；一个十段管线的「全开源」论文，读者实际上没能力逐环审计。

02 / 开放度与配方总览

Axion 1.0 释放两个尺寸：35B-A3B 与 122B-A10B，分别从 Qwen3.6-35B-A3B 与 Qwen3.5-122B-A10B 初始化（还有仅做两段 SFT 的 4B/9B 变体做规模分析）。注意一个容易漏看的细节：两个尺寸用的基座代次不同（122B 用 Qwen3.5、35B 用更新的 Qwen3.6），论文没有解释这个选择——它让跨尺寸对比多了一个混淆变量（§15 的基座对比只在 35B 档内做了控制）。「全开源」的具体清单值得照抄：数据构造、生成、过滤、验证的完整管线 + prompt + 训练代码 + 权重（github.com/bytedance/axion1_0）。配方三段：SFT-I 在自包含推理数据上教模型解难题（可用 Python、禁检索）；SFT-II 从 Stage I 检查点继续，在工具依赖数据上教模型搜资料、读网页、把外部证据与推理计算结合；RL 用 GRPO 在模型自己的工具交互轨迹上继续优化。相关工作里作者把自己放进四条谱系的交点：比 MiroThinker-1.7（中途训练+偏好优化+RL）少两段、比 Agents-A1（域路由 OPD）换掉蒸馏、比 Apodex 1.1 收窄到单 agent；数据侧与 Evol-Instruct/Absolute Zero/Agent0 一脉（任务难度适配学习者）但明确差异——对基座已能解对的题，按它自己的成功策略定向加难；工具任务侧与 TaskCraft/WebShaper/QUEST 互补——先由确定性程序算出答案、再让 LLM 把题面写出来。这个「答案先行、题面后置」的倒置是全文最值得偷的设计之一，§06 展开。

03 / 数据管线 I：种子与组合增强

Stage I 的原料是公开课程、竞赛与推理数据集的问答对（数学/物理/化学/生物/计算机），但不直接训练这些可能已被基座见过的题，而是当种子。第一步「组合（操作 A）」：生成器 LLM 找出种子解法所确立的某个量，构造一道以该量为必要中间结果的新题，要求新题自包含、答案无歧义可检查、且不泄露原种子。论文的 toy 例子值得手算一遍（教学重算）：种子 1+2+⋯+10=551+2+\dots+10=551+2+⋯+10=55；操作 A 令 S=55S=55S=55，新题「求 1+2+⋯+S1+2+\dots+S1+2+⋯+S」；答案 S(S+1)/2=55×56/2=1540S(S+1)/2 = 55\times56/2 = 1540S(S+1)/2=55×56/2=1540——原题的答案变成新题的输入，新题的答案要靠通项公式而不是再数一遍。这步产出的只是「初始增强池」，难化还在后面。

为什么不直接用种子题训练

三个理由都值得展开。污染风险：公开数据集的题大概率在基座预训练语料里，直接训等于复习已会的内容，SFT 增益虚高。难度天花板：课程与竞赛题的难度分布是给人定的，对 2026 年的百 MoE 基座来说，大量种子已无训练价值——论文用基座实测来筛（§04），而不是用人设难度标签。验证独立：新题的参考答案由 GPT-5.5 三解一致独立建立（§05），不继承种子的答案——每道题的「可验证性」是构造时重建的，不是从种子搬运的。

04 / 数据管线 II：模型感知的四难化算子

初始池的每道题都让基座实测一次（允许 Python、禁搜索与网页）。做错的题直接进候选题库；做对的题才触发难化——生成器拿到基座的成功解法，随机施加四个算子之一（这是「模型感知」的含义：难化的方向对着基座的解法策略打）：

  • A 组合：在当前题上再挂一个依赖步，原答案变成新题的中间结果（与 §03 的初始组合同型，可叠加两次）；
  • B 参数化：把固定值换成符号参数，要求给通式而非数值——toy 例：1+⋯+n1+\dots+n1+⋯+n 的答案是 n(n+1)/2n(n+1)/2n(n+1)/2；
  • C 范围平移：把参数范围放大到枚举或捷径失效——toy 例：1+⋯+10121+\dots+10^{12}1+⋯+1012，逐项求和不可行，答案是 1012(1012+1)2=5×1023+5×1011\tfrac{10^{12}(10^{12}+1)}{2} = 5\times10^{23}+5\times10^{11}21012(1012+1)​=5×1023+5×1011（手算：1012×(1012+1)/2=(1024+1012)/210^{12}\times(10^{12}+1)/2 = (10^{24}+10^{12})/21012×(1012+1)/2=(1024+1012)/2 ✓）；
  • D 分情况：加入答案随条件分支的结构——toy 例：1−2+3−⋯±n1-2+3-\dots\pm n1−2+3−⋯±n，nnn 偶数时 −n/2-n/2−n/2、奇数时 (n+1)/2(n+1)/2(n+1)/2（验证：n=4→1−2+3−4=−2=−4/2n=4\to 1-2+3-4=-2=-4/2n=4→1−2+3−4=−2=−4/2 ✓；n=5→−2+5=3=6/2n=5\to -2+5=3=6/2n=5→−2+5=3=6/2 ✓）。

教学要点：四个算子攻击的是解题策略而不是题面长度——组合封「一步出答案」、参数化封「背具体值」、范围平移封「暴力枚举」、分情况封「单一公式套到底」。转化后的题经答案验证即入库，不再要求基座第二次做错（边界句：这是有意的宽松——目标是增加所需推理量，不是保证每题都难倒基座）。这个设计与 Evol-Instruct 的差别论文自己点明：Evol 是「迭代变换加复杂度」，Axion 是「对着你的成功解法定向加难」——前者盲改，后者瞄准。

一道题走完整条难化链（教学重演）

把整条 Stage I 管线在一道题上走一遍（本页构造的教学重演，各步规则均取自论文）：种子「求 1+2+⋯+101+2+\dots+101+2+⋯+10」，答案 55。操作 A 初始增强 → 「令 S=55S=55S=55，求 1+⋯+S1+\dots+S1+⋯+S」，GPT-5.5 三解一致给出参考答案 1540。基座实测：做对了（这题对百 MoE 太容易），其成功策略是「直接套 n(n+1)/2n(n+1)/2n(n+1)/2」。随机抽中算子 C（范围平移）→ 「求 1+2+⋯+10121+2+\dots+10^{12}1+2+⋯+1012」——原策略的公式仍适用但枚举失效，参考答案重建为 5×1023+5×10115\times10^{23}+5\times10^{11}5×1023+5×1011（三解一致 ✓）。轨迹采集：解题 LLM 带 Python 生成轨迹，最终答案与参考比对一致、格式完整 → 入库。这条链的关键节点在「基座做对 → 拿到它的解法 → 定向选算子」：如果基座用枚举法做对了（10 项逐加），C 算子就直接废掉它的策略；如果它用公式，C 算子其实没伤到策略本身、只放大了执行精度要求——这也解释了为什么论文强调「目标是增加推理量而非数值精度」，四个算子里 C 是最接近「精度加难」的一个，其配比权重论文未披露。

05 / 数据管线 III：三解一致与轨迹过滤

参考答案的建立独立于基座预测：GPT-5.5 独立解三遍，三次答案一致且推导过正确性检查才采纳为参考答案；病态题、欠规格题直接丢弃。每次改写后答案都要重建（组合增强后原答案作废）。这个「三解一致」门槛的取舍值得记：它筛掉的是 GPT-5.5 自己也拿不准的题——代价是系统性偏向 GPT-5.5 能稳定解出的题，难度上限被验证器的能力封顶（一道连 GPT-5.5 三次都解不一致的超难题，即使构造得再好也进不了库）；论文用「验证器弱于受训模型怎么办」的代价换了「参考答案绝对可靠」的收益，这是数据工程里典型的可靠性-难度交换。然后由另一个 LLM 在「Python 可用、检索禁用」条件下解候选题，轨迹包含推理、Python 调用与输出、最终答案；与参考答案比对，只保留答案正确、工具调用合法、格式完整、无重复的轨迹。最终数据集形式化：

06 / 数据管线 IV：filter-select-compute-verbalize

Stage II 面向答案依赖外部事实的题。原料是结构化公开数据库（天文/生物/化学/数学/地理/航空等），每条记录有实体、属性、值。出题是四步确定性程序：

  1. Filter：按显式条件筛出候选实体集（例：八大行星中有环的 → 木/土/天/海四颗）；
  2. Select：按极值准则唯一确定一个实体（例：其中质量最小的 → 天王星，14.5 vs 17.1 地球质量，与海王星拉开足够差距）;
  3. Compute：取该实体的属性按确定公式算派生量（含单位换算）；
  4. Verbalize：LLM 把筛选条件与计算要求写成自然语言题面，程序答案为准。

SFT 把 NVIDIA Megatron-FSDP 接进 ms-swift 的 Megatron 后端：ZeRO-3 式参数/梯度/优化器分片 + Megatron 内核。两个有主见的并行选择：不用流水线并行（避免 bubble 与调度的阶段间通信）；MoE 层用专家并行（EP=8）而非张量并行（TP=1）——专家矩阵乘不被切开、不引入额外 all-reduce，expert dispatch/compute 保持在单个 NVLink 域内。上下文并行：FSDP 不分片全部激活，122B 每 token 剩余激活 1.4 MiB+（MoE dispatch 缓冲、GDN 状态、词表 logits），故把序列再切到多卡——全注意力层用 Ring Attention、GDN 层用 Ulysses 式 all-to-all；128K 序列上 CP=4 + micro-batch 2 吞吐最高。账本手算（教学重算）：122B 两段共 841M（I，3h32m）+（II，3h58m）= 7h30m 墙钟 × 32 卡 = 240 GPU 小时 ✓（7.5×32=2407.5\times32=2407.5×32=240）；35B 两段 2h48m ≈ 90 GPU 小时（2.8×32=89.62.8\times32=89.62.8×32=89.6 ✓）；峰值显存 113/101 GiB 每卡。一个 122B MoE 基座的两段 SFT 只花 240 卡时——配方轻量的最硬证据。

异步 RL 与两份一致性

RL 基础设施：rollout（vLLM，10 个 TP4 引擎 40 卡）与 trainer（16 卡，TP2/EP8，优化器态卸载 CPU）分池并跑；服务节点挂 2 个 Qwen3.8-27B 裁判（开放式/引用奖励）与 6 个 Qwen3.5-9B（网页摘要与上下文压缩）。两份训练-推理一致性工程：TITO（token-in-token-out）——消息重渲染再重分词会因 BPE 边界改变 token ID， rollout 与训练用的序列就对不上；TITO 让 agent 循环直接交换 token ID、追加到共享 buffer，训练器拿 buffer 加 policy 位置掩码，压缩后新前缀只在 session 开始分词一次。R3（rollout routing replay）——MoE 下 vLLM 与 Megatron 对同一 token 可能选不同专家；R3 把 rollout 期每 token 每层的专家选择录下来（uint8，约 20MB/样本）在 trainer 前向里回放。诊断数字见 §15。

为什么 BPE 重分词是个真问题（TITO 的具体故障模式）

「重分词改变 token ID」听起来无害，故障模式值得展开（教学重建）：agent 轨迹里工具观测以字符串注入上下文，若训练侧把整段历史重新渲染成文本再分词，观测结尾与 assistant 回复开头的拼接点可能落在不同字节上——例如观测以 "3.14" 结尾、回复以 "5" 开头，rollout 引擎可能持有 token ["3", ".", "14", "5"]（"5" 独立成 token），而重分词后得到 ["3", ".", "145"]（"145" 是词表里的另一个 token）——同一个语义序列在两侧变成不同的 token 串，训练时算的 log-prob 对应的不是 rollout 实际采样的序列，策略梯度就带上了系统性偏差。轨迹越长、观测越多，拼接点越多，偏差累积越大——对平均 2.6 万 token 的长轨迹这不是边界情况而是常态。TITO 的解法是让 token ID 全程不经过字符串态：rollout 产出什么 ID，训练就喂什么 ID，拼接点从根上消失。这与 R3 的 expert 选择回放是同一哲学的两个实例：凡是「两个引擎对同一段内容可能产生不同表示」的地方，就把一侧的决定录下来给另一侧回放。

  5. SEAL-0 上 35B 得 62.2、122B 只有 58.6，且 62.2 是全表最高。能否据此说「信息检索任务上小模型更优」？

    一个数据点、best-of-3 协议、无分解分析。

    展开参考答案

    不能。三个削弱因素：(1) 单基准单尺寸对的孤立反常，没有按检索深度/任务类型分解的机制分析；(2) best-of-3 取最好的协议下 3-4 分差距可能在run 间方差范围内；(3) 两尺寸基座架构不同（Qwen3.6-35B vs Qwen3.5-122B），不是受控规模实验。可说的只是：在这套评测里，更大模型没有在信息检索上兑现规模优势——这本身值得后续工作解释，但不是「小模型更优」的证据。

    §4.2/4.4 Tables 1,3；反常分析见 §15

  6. 如果只有 8 张 H200 想复现这套配方的「最小内核」，哪些部分可行、哪些必然不可行？

    按数据构造/SFT/RL 三块分别估。

    展开参考答案

    可行：数据构造（生成器+GPT-5.5 验证是 API 级；filter-select-compute 是纯程序）；小尺寸 SFT——论文 4B/9B 只做两段 SFT，128K 序列的 9B 全参 SFT 在 8 卡上勉强可行（batch 会很小）。不可行：122B 的复现本体（SFT 要 32 卡起步，账本 240 GPU-hrs 是 32 卡口径）；RL 段（40 rollout + 16 trainer + 服务节点的资源结构，8 卡连一个 TP4 rollout 引擎都紧张）。结论：这套论文的可复现性是「配方级」而非「硬件级」——8 卡用户能复现数据管线与小尺寸 SFT，RL 与大尺寸依赖论文提供的 checkpoint。

    §5 Tables 4-5；账本见 §12、§16
