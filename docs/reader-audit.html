Paper Reading Skill：使用体验、深读能力与可发现性审查

审查日期：2026 年 9 月 24 日。对象包括当前 skill 指令、安装与使用文档、中英文主页、三份完整样例，以及公开 GitHub 仓库。检查了 1440 px 桌面和 390 px 手机视口中的页面结构与横向溢出；核对了示例中的章节、原图、公式与实验入口；查询了 GitHub 仓库元信息、同名仓库搜索及通用网页检索。这里评估的是产品与读者路径，不把构建测试或本人的阅读判断当作独立用户研究。

后续新增了 RAFT 中文深读样例。下文的“三份样例”保留当时审查范围，不代表当前主页的样例总数。

用起来是否顺手？ 熟悉 agent skill 的用户可以照文档开始；第一次使用仍有门槛。 README 给出 Codex 项目内的 CLI 快速安装、Codex／Kimi Code／Claude Code 的个人安装路径、npm ci、新会话和示例提示词；npm run doctor 可在临时目录渲染完整样例来检查本地安装。用户仍需 Node.js 20+、相应 agent 和可访问的论文；该命令不验证 agent 的真实论文读取过程。

从拿到论文到读懂：读者路径

发现与试读。 主页直接展示三份完整案例，英文为默认主页，中文可切换；点击案例即可判断交付形态。这是有效入口。首屏的 MiMo 预览虽然标明为中文案例，但英文访客须向下浏览才能看到英文成品。方法依据此前只在页尾一句话中出现，用户难判断“图谱”背后有无阅读协议；本次已把方法说明提升为主页和两份 README 的独立章节。

安装与调用。 Codex 项目内现在有 CLI 快速试用命令；个人安装仍给出两种 skill 目录、Node 版本、更新命令及一个可复制的请求。实际链路是“安装 skill → 安装渲染依赖 → 重开 agent → 提供论文 → 等 agent 完成阅读与生成”。它依赖 agent 的论文读取能力；仓库不是独立 PDF 转换服务。对于只想试一次的人，依赖与代理环境的准备成本仍然存在。旧版 npm ci --prefix 曾在自定义目录名下失败，文档已改为进入安装目录执行 npm ci。已在隔离目录验证 CLI 从 GitHub 拉取和安装已有版本，也验证本地新版本安装后运行 npm run doctor；下一项仍是由 Codex／Claude Code／Kimi Code 各自完成真实论文读取的冷启动记录。

阅读产物。 三例都把重要知识放在同一 HTML 内，并把原论文图放在解释附近；原文页码可按需显示。手机上原图曾随容器缩到约 354 px，图内小字难读；本轮把窄屏图片改为图框内横向滚动，保留约 900 px 的图宽和键盘焦点。读者仍要平移阅读大图；长公式虽能局部滚动，也需要主动发现完整表达式。Transformer 和 DeepSeek 的编辑图曾把不可点击的 01–06 列表画成导航，首页 MiMo 预览也有同类问题；本轮改成“论文问题 → 机制 → 证据／成本”的关系图，并把真正的章节导航留在 HTML 中。更深的障碍是背景知识跨度：当前文档解释核心机制，但缺少针对陌生读者的理解检查和“读不懂时从哪里补”的路径。

判断是否真的读透。 现有样例能让读者追踪论文的主要论证，也能查到关键实验的设置、对照、指标与结果。它们不能证明任意论文都会达到相同深度，也不能证明读者仅看产物能正确解释公式、复现实验设定或分清作者结论与编辑推断。技术报告样例集中在 AI／系统领域；理论、数据集、综述和非计算机学科的输出能力尚未通过样例检验。

方法论与可信度

本项目的方法应表述为有来源的设计综合，而不是已经过实验验证的独立科学阅读理论：

  1. Keshav 的三遍阅读法提供由全局到细节的阅读深度；skill 将它用于内部理解过程，默认交付完整深读。
  2. Novak 与 Cañas 的概念图理论要求焦点问题、带语义的连线和跨区关联；skill 据此让图回答论文问题并解释箭头。
  3. SciDoc2Diagrammer-MAF报告了自动生成科学图示的不完整和不忠实问题；skill 因此要求图、数字、公式与原文对应。项目没有实现该论文的算法。

三条依据经编辑转成“全局图 → 主路径 → 机制放大 → 实验图谱 → 综合理解”的读者顺序。深读的验收对象是读者能否回答：论文解决什么、作者为何作出关键设计、机制如何运作、关键实验实际测了什么、证据支持到哪里。 公开质量门槛和三例读者题目已把这些问题具体化；版式完整、图形好看和构建通过仍不能替代真实读者答题。

按用户提供的 GitHub 搜索条件 在 2026-09-24 查询，结果含课程仓库和与论文阅读无关的项目；星标只反映关注度，不能直接证明深读质量。下表只取与单篇论文阅读相关、且 README 中能核实功能的仓库。

项目 从公开说明能确认的长处 本项目应吸收的能力
DeepPaperNote（约 1.1k stars） 面向 Obsidian 的持续笔记；npx skills add 安装；明确初次使用的语言／保存位置；公开笔记质量量表与回归流程。 降低首次试用成本，公开可执行的阅读质量验收；保持本项目“一篇论文、一份可离线读完的 HTML”的差异。
PaperForge（约 580 stars） 强调重建作者推理、方法直觉、公式推导、实验分析与后续想法。 在机制段检验能否讲明“为什么这样设计”，而非只复述模块顺序。
sodalone/paper-reading-skill（约 138 stars） 把主张、证据和判断对应起来，区分可获得原文与信息不足的情况。 为每个重要结论保留可追溯的证据链；源材料不足时标出缺口，不生成完整深读的假象。

这轮不把 Zotero、Obsidian 或论文管理仪表盘直接并入 skill。它们服务长期资料管理，当前最紧迫的读者问题是产物是否真的让人读懂论文。项目的可辨识价值应是：从论文问题到机制、公式、原图与实验的单文件视觉深读；对照项目的质量量表，进一步把这种承诺变成可观察的测试，而非一句宣传语。

推广：先让需要的人找到，再让他们相信

仓库已具备可访问主页、英文默认与中文版本、GitHub 描述/topics、三份公开成品及元数据标签。当前仓库创建时间为 2026-09-22，只有很短的传播周期；泛词搜索又与许多同名项目竞争。仅靠名称和 topics，无法让用户理解这里的差异：一份可离线阅读全文的 HTML，将机制与实验证据放在同一阅读路径上。 本次已在主页和 README 首段写出对象、输入、交付物，并新增有来源的方法章节。搜索是否改善须在索引更新后重新采样，不能由代码提交直接推断。

推广材料应围绕完整成品，而不是功能口号。三篇示例可分别对应“经典方法论文”“模型与服务系统报告”“RL 训练报告”的检索意图；每篇的入口需要说明读者会学到什么、文章版本和原图出处。后续可将真实读者任务结果、修订记录与覆盖更多学科的案例公开，再向相关 skill 目录、研究工具列表及读书社群提交项目。外部目录收录与用户推荐需要另行执行和验证。

按收益排序的下一步

顺序 改进 可验证的完成标准
1 独立读者任务。 用现有题目找未参与编写的人，仅看三份 HTML 回答机制、公式、实验和限制；记录错误、回读位置和是否必须打开 PDF。 按公开答案形成错误清单，并按误解修改文档；清楚区分“页面有内容”和“读者真正理解”。
2 真实首次使用链路。 在全新环境按 README 安装并运行 doctor，再由 agent 从真实 PDF／URL 生成一份个人 HTML；给出成功产物路径和失败诊断。 Codex、Claude Code、Kimi Code 各至少完成一次可重复的冷启动记录；文档能独立指导用户。
3 科学事实抽查。 对三例逐个核对关键公式、图示箭头、原图解读、实验表格数字和条件。 形成源对象到产物对象的核对清单；错读修复有记录，不能以渲染测试代替。
4 手机上的图和公式。 在已有图框内平移的基础上，加入能保留全局位置感的放大路径，并给过宽公式明确滚动提示。 390 px 视口可读原图小字与完整公式；仍无整页横向溢出，键盘可操作。
5 扩大论文类型和检索入口。 增加理论或证明论文、数据集／基准论文；补各样例的独立介绍和可检索元信息。 不强套训练流水线图；能从相关论文问题找到案例，并在后续相同检索中观察入口变化。

本轮又加入了可执行的安装自检、公开的质量门槛和三篇样例的读者任务，并将作者设计推理写入 skill 的深读要求。真正的深读效果仍要靠第 1 项独立读者任务验证。
