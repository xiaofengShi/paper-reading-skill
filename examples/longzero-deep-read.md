# LongZero 深读：零数据的长上下文推理强化学习

深读对象：LongZero: Enhancing Long-Context Reasoning in LLMs from Zero Data（arXiv 2610.30132v1，清华大学 TSinghua-Bosch 联合 ML 中心，Wan 与 Chen）。RLVR 让短上下文推理吃到了红利，但长上下文 RL 的训练数据要同时满足长、多样、有难度、可验证四个条件——人工标注贵、自然语料稀缺、现有合成管线全都要靠外部语料或更强教师模型。LongZero 的回答是把这个依赖整个砍掉：**让被训练的模型自己给自己出长上下文题**。关键洞察是生成顺序的反转——先写紧凑的「问题+证据+答案」结构化规格（答案在长文本存在之前就固定了），再把证据展开成长文档；配合自写检索任务与「不稳定带」难度过滤，用 GRPO 训练。两个基座、五个基准：零外部数据的 LongZero 平均分全面胜过基于外部语料的两种合成数据，甚至胜过 397B 教师模型写题验证的基线。

## 01 全景：这篇论文在做什么

长上下文推理（报告合集、长对话、整本书）的 RL 训练数据是出了名的难造：有用的数据要（i）够长（ii）需要证据检索与整合（iii）够难以产生学习信号（iv）答案可自动验证（PDF §1）。现有管线全部依赖外部资源——短多跳 QA 扩干扰文档（LoongRL）、真文档上让模型出题（SPELL/QwenLong 系）、知识图谱+搜索轨迹（LongTraceRL）、或直接请更强教师出题。外部依赖有两个深层问题：教师随被训模型变强而愈发难找；真实语料引入混淆——模型可能凭参数记忆答题而非读上下文，公开文本还可能污染评测集。零数据 RL（模型自己出题自己学）在数学/代码/游戏/工具等**短上下文**域已证明可行（Absolute Zero、R-Zero 等），但没人解决过长上下文版本的核心困难：任务=长输入+关于它的问题，两者都要模型造，而一个还不会长上下文推理的模型，不可靠地写或验证关于长文本的问题。

这个反转为什么成立，值得逐句拆：如果先写长文再出题，出题与验证继承的正是要训练的弱点（不可靠的长上下文推理）；而先写短规格，规格层面只需要模型**已经可靠**的短上下文能力（写结构化 JSON、查引用一致性），长文本只在展开环节出现，且可以被程序化的忠实门检查（答案或别名须逐字出现在展开文本中，否则整题丢弃，PDF §3.1.1）。

## 03 核心机制一：两类自合成数据

**推理数据**（𝒟_rea）从「世界」抽样：程序先采样领域、文体集合与风格卡（时代、命名风格、禁用名，保证多样性），然后策略 π_θ 写严格 JSON 的世界规格 𝒮=(𝒱,ℱ,ℱ⁻,𝒬)：

- 𝒱 实体集——**至少两个人同姓、至少两个机构名高度相似**（构造天然干扰）；
- ℱ 原子事实，构成 Q 条部分共享桥实体的问题链，问题 q 有 H_q 跳；
- ℱ⁻ 干扰事实——每链 K_q 条，涉及同一桥实体但角色/时间/属性不同；
- 𝒬 问题集——每个问题以描述指称中间实体（如「该杂志母出版社的创始人」），答案必须是某条事实中逐字出现的具体名字/地点/产品/标题/数字。

难度由设计变量控制（Eq. 1，作者明说是设计指南而非拟合模型）：Difficulty(x,q) ∝ |x|·H_q·K_q——规格控制跳数与干扰数，展开控制长度。之后是**计划与展开**：把 ℱ∪ℱ⁻ 的每条事实分配到 M 篇文档（同一问题的支持事实分散到不同文档、每条干扰远离它模仿的事实），各文档按计划文体独立撰写、每条事实恰好陈述一次；最后程序打乱文档顺序并执行**忠实门**——答案或等价别名未逐字出现在展开文本中的问题直接丢弃。

**检索数据**（𝒟_ret）走 MRCR 任务格式：模型只拿到取自公开 MRCR 数据集的少量格式词与常见名词，自己对每个「写一个关于{名词}的{格式}」请求回复 R 次，形成自写回复池；**程序**从池中拼装样本——选一个目标请求，把该请求的 N 条自写回复（针 a_1…a_N）随机插入其他请求的回复之间直到对话达到设定长度，最后要求复现「前缀 s ∥ 第 k 条针」。因为哪条是第 k 针由程序决定，参考答案 y*=s∥a_k **构造即正确**；解题要求在长对话中区分模型自己的近重复回复并追踪顺序（PDF §3.1.2）。采样 1,152 训练 + 128 验证对话，不过滤。

## 04 核心机制二：不稳定带过滤与 GRPO 训练

**难度过滤**的动机来自 GRPO 的组内归一化：对同一提示的一组 G 个回复，全对或全错的题归一化后优势为零、不产生梯度（Eq. 2）。LongZero 让 π_θ 用与训练奖励相同的匹配规则分小波次自答每题，**一出现一正一误即保留、前 W 个答案一致则丢弃**；检查还发现持续全错的题常是缺陷题（如两文档给同一属性赋了冲突值）。由此难度自动贴合出题者：Table 1 显示 Qwen3-8B 只保住自己题的 13.1%（4B-Thinking 为 17.7%），同样数据量需合成更多世界——更强的长上下文模型写的规格更忠实、浪费更少，这直接解释了 §05 中「4B-Thinking 提升更大」的现象。最终训练集固定为 2,304 道推理题 + 1,152 段检索对话（2:1）。

**训练目标**（Eq. 2–5，逐项展开）：GRPO 去掉 PPO 的价值模型，用组内平均奖励做基线，优势为组标准化形式

$$\hat{A}_{i,t}=\frac{r_{i}-\operatorname{mean}(\mathbf{r})}{\operatorname{std}(\mathbf{r})}$$

（同组所有 token 共享该优势）；遵循 DAPO 采用**token 级**策略梯度——先对组内全部 token 求和再平均（Eq. 3 的 1/Σ|o_i|），而非先输出内平均；裁剪项 clip(ρ_{i,t}, 1−ε, 1+ε) 限制新旧策略比率，ε=0.2；KL 惩罚**加在损失上而非奖励里**（β=0.001），用 k3 估计器逐 token 估计：D̂_KL = κ_{i,t} − log κ_{i,t} − 1，其中 κ 为参考策略与当前策略的概率比（Eq. 5）——该估计量在比率接近 1 时近似 KL、远离时由 −log 项主导为正，保证非负且低方差。基座：Qwen3-4B-Thinking-2507 与 Qwen3-8B(thinking)，verl 实现，恒定学习率 1e-6，每步 64 提示 × G=8 回复，上限 32,768 提示 + 8,192 回复 token，分别训 72/108 步（约 1.3/2 epoch）；**所有基线共用同一 RL 配置与检查点步数**，差异只在数据源。

**奖励设计**（Eq. 6）：推理题要求输出以「The answer is <答案>」结尾，取最后一个后的文本 ŷ——当且仅当 ŷ 以整词跨距包含某参考答案（答案及其别名）且长度至多比参考答案长 L 个字符时给 1，否则 0；匹配前统一小写、引号、标点与空白。整词匹配防「15 匹配 5」，长度限制防列举一堆候选蒙对。检索题：最终答案不以随机前缀 s 开头直接 0 分；否则按 MRCR 官方做法取剩余部分与目标针的 difflib SequenceMatcher 相似度作**稠密奖励**——近似复现可得部分分。

## 06 综合评述

机制与证据的咬合点有三个。其一，顺序反转把「出题可靠性」从长上下文能力剥离到短上下文能力+程序检查上——规格短可校验、答案构造即对、忠实门程序化，三层保证让「零数据」没有以牺牲可验证性为代价（§3.1.1）。其二，不稳定带过滤让数据难度内生地跟随策略能力演进，这既是效率设计（GRPO 零梯度题不浪费）也是与教师合成基线的本质区别——397B 教师写题再验证，题目难度仍然错位于策略（§4.2）。其三，两类数据的互补性由消融直接支撑：推理练串联、检索练精确定位，单项各有回退基准，2:1 是唯一全面不降的配置（Table 3）。

证据边界同样清楚：增益量级温和（4B 平均 +2.7、8B 平均 +1.0），教师基线差距在 1 分上下，且所有方法共用同一检查点步数而非各自最优——「零数据最优」成立，但「碾压」谈不上；8B 的 AA-LCR 近零分是窗口吞吐约束，方法归因要剥离；训练上下文最长约 32K，长度泛化只在 4B 上得到验证；论文自陈的未来工作第一条就是**迭代化**——训练后的模型重新生成并再过滤自己的数据，这恰好把它接进了本周 RSI 综述的语言：LongZero 目前改进的是任务策略 h（数据管线本身还是一次性的人工设计 B），迭代化之后才真正触及「改 U」。

一句话收束：当训练数据的瓶颈从「找题」变成「保证题对」，答案正确性可以由构造与程序保证、难度由出题者自己标定——LongZero 用生成顺序的一次反转，把长上下文 RL 从外部语料依赖里解放了出来。
