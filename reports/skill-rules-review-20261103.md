# Paper Reading Skill：规则复审与精简

日期：2026-11-03。范围：执行入口、全部参考规则、质量门槛、初始化模板、调用提示与中英文说明。基线为 `5ebdaaf`。这是作者／AI 辅助的规则一致性审查，不是真人阅读实验；没有重新验证画廊中每篇论文的科学结论。

本次保留的核心是：**默认面向具备相关领域基础、第一次读这篇论文的科研工作者；解释量按读者背景调整，技术覆盖按 Brief／Deep 分别控制。** 独立可读要求把论文特有的机制和证据解释完整，不要求重讲读者已有的领域基础。

## 发现与处理

| 问题 | 调整后的规则 |
| --- | --- |
| 默认科研读者与“科研证据视角仅按需启用”并存；中英文首页仍残留固定教学顺序 | 区分读者背景与审稿／研究比较任务。默认科研读者，批评与研究卡仍按请求启用。 |
| 解释校准、背景补充、独立阅读、交互检查在多个文件重复 | 入口保留原则和路由；读者校准、独立交付、视觉规则各有一处详细说明，质量门槛引用它们。模板只留任务提示。 |
| 每个难点都按“场景—图—算例—公式”排列，Deep 每个公式都附算例 | 由论文和读者决定顺序。例子用于补关键推理缺口；Deep 保留完整推导和技术覆盖，熟悉的常规代数无需反复教学。 |
| 每个静态视图都要说明为何不交互，缺少可选工具可能被视为失败 | 只有交互能揭示实质关系时使用；重要交互模型记录假设和检查，静态视图不写例行决策台账。工具本身不决定质量。 |
| 图片必须另写前置段落，质量规则暗含所有交付都必须 HTML、必须找真人试读 | 图片可用相邻说明或实质性图注解释；用户明确指定的格式优先。真人评估明确为按需、有人可参与时进行。 |
| 旧评审矩阵把每条质疑都转成实验、把最大消融增益视为唯一贡献 | 接受证明修复、协议澄清、代码核验等证据；评估贡献须结合不确定性、交互和成本，不由单次增益决定。 |
| 只要代码公开就核对全部机制，并假定代码更可靠 | 代码检查用于请求所需或重要歧义，先核对版本和身份；代码与论文均须结合证据判断。 |
| 模式说明仍把所有已发布样例称为 Brief | 以每篇文档声明的模式为准，旧文件名和链接保留。 |

## 规则分别放在哪里

- [执行入口](https://github.com/xiaofengShi/paper-reading-skill/blob/main/SKILL.md)：深度、受众、阅读底线与参考规则入口。
- [读者校准](https://github.com/xiaofengShi/paper-reading-skill/blob/main/references/learner-experience.md)：哪些必须解释、哪些只补桥梁、哪些省略；交付前同时检查缺口与冗余。
- [独立阅读与分享](https://github.com/xiaofengShi/paper-reading-skill/blob/main/references/standalone-delivery.md)：正文自足、出处集中末尾、按授权发布及真实链接核验。
- [视觉与交互](https://github.com/xiaofengShi/paper-reading-skill/blob/main/references/visual-reading.md)：图何时有用、交互何时值得、可访问性与静态替代。
- [质量门槛](https://github.com/xiaofengShi/paper-reading-skill/blob/main/evals/reading-quality.md)：可核验的交付条件和深度标准。
- [渲染输入契约](https://github.com/xiaofengShi/paper-reading-skill/blob/main/references/renderer-format.md)：实际语法、数值限制和离线资源约束；不改动渲染器 API。

入口从 14,620 缩至 7,006 个 UTF-8 字节，减少 52.1%；入口、调用提示、质量门槛和全部参考规则合计从 90,693 缩至 73,075 字节，减少 19.4%。统计不包含本报告、README、生成 HTML 或初始化代码，避免把历史报告与运行规则混算。体量变化只说明精简幅度，不证明阅读效果。

## 三种读者如何处理同一机制

假设论文在某个分支使用停止梯度操作。以下是规则情境核对，不是对真实读者的试验：

| 读者 | 应解释 | 可省略 |
| --- | --- | --- |
| 本领域 ML 科研工作者 | 哪个分支停止梯度、仍由哪个目标更新、为何如此设计及支持证据 | 通用反向传播入门 |
| 跨领域科研工作者 | 上述论文特有机制，加上理解梯度路径所需的短桥梁 | 与机制无关的 ML 课程 |
| 明确缺少 ML 基础的数据工程师 | 上述机制，加输入、预测、损失、更新的必要中间步骤或算例 | 不影响任务的完整优化理论课程 |

三者都可以选择 Brief 或 Deep。改变读者背景不降低 Deep 覆盖标准，也不把 Brief 变成术语清单。教程交付前必须通读全文和推荐路线，修补必要缺口，同时删除重复背景；审查记录留在审计源，正文直接讲主题。

## 保留的约束与边界

论文身份和版本、数字与分母、实验可比性、作者陈述与推断的区分、关键限制和负结果均保留。Deep 仍要求覆盖记录、核心内容无遗漏、所有适用维度达到 3；Brief 的解释标准不变。独立可读、出处集中末尾、离线可用和公开分享核验继续适用。

本次不改已有教程的初学者定位和内容，不重写历史报告，不新增模式或依赖。自动化和 AI 自审不能证明真人理解效果。
