**先给结论：一批数据对模型有帮助，至少需要分别核验“进入正确版本、获得训练暴露、形成有效监督、参与实际更新、改善独立评测”。** 前四项是学习发生的工程条件；最后一项才开始回答能力有没有改善。即使参数变了，也不能据此确认这批数据带来了收益。

交付一批数据，只是训练链的起点。数据要进入正确版本，被实际读取，提供有效目标，推动参数更新，最后还要在独立场景中接受评测。任何一环断开，都可能出现“数据交付成功，模型表现却没变”。

这份教程从一条施工绕行样本出发，把整条链讲清楚。先用图和小实验建立直觉，再学习对账字段、代码与评测方法。每一步都说明发生了什么、怎样检查，以及结果能说明什么。

## 01 / 从一条施工绕行数据开始

假设车前方摆着施工锥桶，驾驶员提前减速，向左绕开封闭区域，再回到可行驶车道。数据团队交付了一段记录：历史图像、车速、导航、目标轨迹以及标注有效性。

先看下图：车现在能获得的是历史图像、车速和导航；蓝色虚线是**之后**驾驶员走出的轨迹。训练时可以用它来对答案，部署时不能把未来答案当输入。

*施工绕行教学示意。蓝色虚线是训练时用来对答案的未来轨迹，不是模型当前已知的输入。*

### 先分清：训练模型与使用模型

这里的一条**样本**，是围绕某个决策时刻整理的输入与目标，不一定是一整段视频。**输入**是当时能知道的历史图像、车速和导航；**目标，也叫监督标签**，是训练时用来对答案的记录。轨迹可以写成“0.5 秒后在哪里、1 秒后在哪里……”的一串坐标。这里的“专家”指示范驾驶员或其他有效参考来源，并不保证每一次示范都是唯一最优解。

模型是一套把输入变成预测的计算规则，其中有很多可以调整的数字，叫**参数**。训练先用当前参数做预测，再和目标比较，按误差调整参数；重复许多次，尝试让这套规则在所关注的任务上表现更好。它通常不靠逐条检索训练视频来作答，但仍可能记住训练样本，所以“在旧样本上答对”还不够。

| 正在做什么 | 输入与目标怎样使用 | 哪些东西会改变 |
| --- | --- | --- |
| 训练：用示范改进计算规则 | 模型先看输入作预测；训练程序另用目标比较误差 | 优化步骤调整参数，之后再用新参数预测 |
| 推理：使用已训练的规则 | 模型使用当前可获得的输入预测未来，拿不到未来答案 | 常规推理不按未来标签更新参数；后续输入会随时间变化 |

**训练产物主要是一组参数及其配套配置。** 把更多视频上传到数据池，不会自动改动正在使用的模型；需要训练任务实际消费数据、产生更新，再选出和部署合适的模型版本。后文提到的 loss 是“比较预测与目标的误差评分”，batch 是“一次一起计算的一组样本”，梯度是“怎样调参数的局部方向线索”。先有这幅全景，后面再逐项拆开。

这段数据可以教模型什么，取决于训练任务。训练目标若是识别锥桶，标签可能是框或分割区域；若是预测其他车辆，标签是其他车辆未来运动；若是规划本车，标签可以是专家未来轨迹。**场景标签“施工”本身，并不自动变成“绕开施工”的监督。** 需要检查它对应哪个输出、哪项损失，以及哪个训练版本。 [7](#ref-r7)

这里先记住两个词就够了：**样本清单（manifest）**决定这次训练选用了哪些数据；**监督**是拿来对答案的目标。后面的 batch、mask、梯度等术语，遇到时再解释。

这里的“链”是诊断顺序。要证明新增数据**导致**收益，还需要后面介绍的匹配对照；它不是凭日志就能建立的因果结论。

## 02 / 数据版本是一份明确的输入合同

**数据池**保存可用数据，像仓库货架；**训练版本**固定这次选用的样本，像发货单；**实际读取流**记录训练真正消费了什么，像出库流水。三者应该能对账，但不能混为同一个数量。

要让同一条样本可追踪，至少需要身份、版本、时间、单位、输入与目标的语义约定。下面是一份可按平台调整的参考 schema，并非 PyTorch 强制格式。

`sample_id` 回答“哪条样本”；`drive_id/scene_id` 回答“来自哪个相关场景”；哈希回答“内容是否变化”；版本回答“采用哪套数据与标签规则”。**相同 ID 的文件被覆盖，仍可能读到新内容；相同内容也可能被多个 ID 重复登记。** 因而身份检查与内容检查都需要保留。

`anchor_timestamp_us` 是作出决策的时刻，以微秒表示。`history_offsets_s` 的负数表示往前看，`target_offsets_s` 的正数表示之后要预测的时刻。`ego_at_anchor` 表示以这一时刻的本车为坐标参考；同一个坐标数字，换了原点或方向就会表示不同位置。

历史输入只能使用当时可获得的信息；未来轨迹通常作为监督标签存在，不能误放到输入特征里。“训练表中存在未来列”与“模型输入访问未来列”是两件事。可以沿着“读一条记录（`Dataset.__getitem__`）→ 组成一批（batch）→ 调用模型（`model(...)`）”检查实际传参。

格式校验还要越过“字段非空”：坐标系是否一致、距离是否用米、速度是 m/s 还是 km/h、轨迹是位置还是位移、姿态角是度还是弧度，都会改变数字的意思。建议把这些语义写进 schema 版本，并抽取可视化样例或做几何一致性校验。

**最小验收动作**：冻结清单与哈希；确认训练配置引用该清单；随机回查若干样本；统计新增样本按原因被拒绝的数量；读取日志里回传同一份 manifest 身份。只拿到一个数据目录链接还不够。

## 03 / 先切分场景，再切分训练样本

一段驾驶日志可以切成许多训练窗口。10 秒视频按 10 Hz 取锚点，理论上可产生约 100 个窗口；实际数量还受历史长度、未来标签长度和过滤规则影响。**窗口数不等于独立场景数。** 相邻窗口很可能共享大量图像和未来轨迹。

这里的 **split 是集合归属**：训练集用于调整参数，验证集用于选择配置或模型版本，测试集用于检查选定方案在未参与选择的数据上表现如何。三者可以放在同一张清单里，但读取用途要隔开。把同一事件的近重复记录分到训练和测试，会让“陌生题”变成近乎见过的题，这就是一种**数据泄漏**。

如果先生成窗口，再随机把每个窗口分到训练与测试，相邻时刻可能跨集合。模型在测试中看到近乎同一辆车、同一个锥桶和同一段轨迹，你得到的更像“邻近样本回忆能力”。数据工程师可以先按驾驶日志、完整场景或更严格的路段/日期分组，再分配集合；采用哪一级分组，取决于你希望验证哪种泛化。

把同一场景看成一条胶片：左侧把相邻窗口混进不同集合，右侧先保留场景边界。

![图解：场景分组小图：同一事件的重叠窗口随机分组会跨集合，先按场景分组可以避免这一类身份交叉。](assets/scene-split.svg)

*分组教学示意，不表示实际切分比例；其他近重复与泄漏仍需另行排查。*

| 你想判断的能力 | 建议额外隔离的维度 | 仍需留意 |
| --- | --- | --- |
| 同类新场景 | 完整 episode / scene / drive | 同一事件的重复上传与重叠窗口 |
| 新道路或城市 | 路段或地理区域 | 地图、传感器、交通规则同时变化 |
| 新时间条件 | 日期、天气、光照窗口 | 同路线多次采集的外观相似性 |
| 新标注规则 | 标签版本 | 规则变化本身可能改变分数 |

表中是实验设计建议，不能把“按 drive 分组”当成对所有泄漏的完整防护。重复传感器文件、缓存特征、预训练数据交叉也要按任务排查。

一个常用的对账查询如下。理想结果是空表；若有同一 `drive_id` 出现在多个 split，就需要解释或重新切分。它只能发现这类身份交叉，不能识别全部近重复。

```sql
SELECT drive_id, COUNT(DISTINCT split) AS split_count
FROM dataset_manifest
GROUP BY drive_id
HAVING COUNT(DISTINCT split) > 1;
```

归一化用到的均值、方差等统计量通常也应只在训练集合拟合，再固定用于验证与测试。否则，评测集合的信息会进入模型准备过程。常数化的单位换算与使用评测数据估计统计量，需要分开看。

**归一化**可理解为按约定把数字变换到便于计算的尺度，例如车速减去训练集均值，再除以训练集标准差。标准差描述数值的分散程度。这些统计量也是处理规则的一部分，应该随版本保存，不能每读一批测试数据就重新估计一套。

## 04 / 采样决定有限预算里看见什么

`Dataset` 定义一条样本怎样取，`Sampler` 决定取哪些索引，`DataLoader` 组织读取和 batch。对于流式 `IterableDataset`，选择逻辑可能在迭代器内部，不能假定一定存在独立的索引采样器。PyTorch 对这些职责有明确区分。[1](#ref-r1)

把它对应到熟悉的数据管道：`Dataset` 负责“给一个 ID 或索引，读出输入和目标”；`Sampler` 给出这轮要读的索引序列；`DataLoader` 按序列取记录并组成批次。**一次采样是选择，一次消费是记录成功进入本次训练计算。** 选中了却解码失败或被丢弃，不能算成功消费。

数据团队最需要区分三个计数：**抽取次数、成功消费次数、去重样本数**。同一条困难样本抽了 100 次，既不是 100 条新数据，也不代表获得了 100 种新路况。

### 一个固定预算的例子

以下全部为教学设定：100 万条数据，施工样本 1,000 条，占 0.1%；预算为 1,000 个 batch，每批 32 条，合计 32,000 次抽取。假设每次独立、有放回、等概率抽取。

**有放回**表示抽到后仍可再次抽到，序列可以是 A、A、B；**无放回**则在这轮抽完前不重复。这里的 32,000 是抽取总次数，不是必须不同的 32,000 个 ID。施工这类占比很低的场景也常被叫作**长尾场景**。

| 要观察的量 | 计算结果 | 对数据工程的意义 |
| --- | ---: | --- |
| 施工样本抽取次数的期望 | 32 次 | 数据入库很多，不说明本次训练暴露很多 |
| 一个 batch 至少出现一条施工样本 | 约 3.15% | 施工监督只会出现在少量 batch 中 |
| 某一条指定施工样本的期望出现次数 | 0.032 次 | 不要用总类目暴露代替单样本覆盖 |
| 这条指定样本一次也未出现的概率 | 约 96.85% | 本次完全没见过它并不反常 |
| 施工抽样比例改为 20% 后的预计次数 | 6,400 次 | 暴露增加，也带来更多重复与目标偏移 |

这些值由附带的 `math_lab.py` 运行核验。它们不适用于无放回完整遍历、动态采样或强相关批次，不能直接拿去解释所有训练任务。

表中的**期望**是相同规则反复运行时的平均数量，不是一次运行保证出现的数量。32 来自 $32000\times0.001$；把抽样比例改成 20%，则是 $32000\times0.2=6400$。单次可能多一些或少一些。改变抽样比例只改变“多常看见”，并不会自动补出新的路况。

<details class="reading-detail">
<summary>选读：这些概率怎样算出来</summary>

设施工占比为 $p=0.001$，抽取次数为 $D=32000$，batch 大小为 $B=32$。施工抽取次数的期望是 $Dp=32$；一个 batch 至少有一条施工样本的概率是 $1-(1-p)^B\approx0.03151$。

设总样本数为 $N=1000000$，指定一条样本在每次抽样中概率为 $1/N$，因此从未抽到的概率为 $(1-1/N)^D\approx0.96851$。这说明“整个施工类见了 32 次”不意味着 1,000 条施工样本都被见过。

若给每条施工样本相对权重 $r$，普通样本权重为 1，施工抽样占比是 $q=rp/(1-p+rp)$。解出 $r=q(1-p)/[p(1-q)]$。把 0.1% 提高到 20%，需要 $r=249.75$，不是简单乘 200。

</details>

### 过采样会改变训练任务的侧重点

把施工场景从 0.1% 抽到 20%，会让训练更重视施工。它可能有助于专项能力，也可能损伤其他场景；“权重大就一定更好”不是结论。若 loss 又额外给施工样本乘 10，两个权重会叠加。

在简化的两类目标中，施工 loss 的归一化系数份额会从 20% 升到 $0.2\times10/(0.8+0.2\times10)=71.43\%$。**这是目标函数的系数份额，不是实测梯度贡献占比**；后者还受样本误差、梯度方向和优化器影响。

可以用 100 份损失来理解这次加权：20 份施工、80 份普通，原本每份系数都是 1。给施工每份乘 10 后，施工总系数变成 200，普通仍是 80；施工占 $200/(200+80)=71.43\%$。损失权重改变“对哪类错误更在意”，与采样改变“读到哪类数据”是两个环节。

## 05 / Batch 是有语义的对齐结果

**batch（批次）**是一次送入模型的一组样本。**collate（组批）**把这些样本整理成能一起计算的张量。长度不同时，可用 **padding（补齐）**把形状补到一致，再用 **mask（有效性标记）**指出哪些位置是真实、有效的，哪些只是占位。

**张量（tensor）**在这里就是按多条轴排列的数值数组。形状（shape）说明每条轴有多长；`[B,K,2]` 描述尺寸，不是三个实际数据值。比如 `B=2、K=3`：一次有 2 条样本，每条有 3 个未来时刻，每个时刻存 x、y 两个坐标，共 12 个数。第一条样本可以是 `[[1,0],[2,0],[3,0]]`，对应的有效性为 `[true,true,false]` 时，最后那个点不参与该项监督。

沿时间轴看一次组批：输入来自当时可获得的信息，监督来自未来记录；补齐位置仍要单独标记是否有效。

![图解：历史输入与未来监督时间轴：当前时刻之前是可用输入，之后的轨迹作训练目标，无效占位用斜纹表示。](assets/time-alignment.svg)

*时间轴为教学示意；底部 1.5 米是 15 m/s × 0.1 s 的匀速估算。*

一个面向规划的教学 batch 可以这样组织。这里的维度是示意，不是 UniAD 或 nuPlan 的固定接口。

| 字段 | 形状示例 | 含义与检查 |
| --- | --- | --- |
| `images` | `[B, T, V, C, H, W]` | batch、历史时刻、相机、通道、高、宽 |
| `ego_state` | `[B, T, D]` | 速度、姿态等；字段顺序和单位固定 |
| `navigation` | `[B]` 或任务规定形式 | 当前可获得的导航指令 |
| `future_xy` | `[B, K, 2]` | 未来 K 个时间点的本车坐标，单位米 |
| `target_valid` | `[B, K]` | 哪些目标点允许进入监督 |
| `sample_id` | B 个字符串 | 连接读取、loss诊断与场景回看 |

`B=8` 表示 8 个样本，不是 8 帧视频。历史维度 `T` 和未来监督维度 `K` 是两个对象。缺帧 padding 也不能让目标点自动变成有效。

例如 `images` 的形状为 `[2,3,6,3,256,256]`：2 条样本，每条含 3 个历史时刻、每时刻 6 路相机，每张 RGB 图有 3 个颜色通道、高宽均为 256。这里共有 36 张图，但仍然只有 2 条样本；图像数量和样本数量不是同一个分母。

**时间对齐例子**：若车速为 15 m/s，传感器与标签错开 0.1 秒，车辆在这段时间就会前进约 1.5 米。这是简单的匀速教学估算，实际误差还受转弯、外参和插值影响。张量 shape 完全正确时，语义仍可能错位。

**数据增强**是对已有样本作受控变化，生成训练时的另一种呈现。图片水平翻转时，横向坐标、转向符号、相机顺序与左右导航也可能需要改变。不要只翻图，不改标签；也不要在未核实坐标约定时机械取反所有字段。DAVE-2 使用位姿扰动时会相应调整目标转向，说明增强应作用于成对的输入与监督，而不只是图像外观。[6](#ref-r6)

padding 只是在数组里放占位值；mask 才声明哪些位置可用。两者不能互相替代，补成同样长度也不等于补出了真实标签。

建议 batch 级日志保留：成功解码条数、缺失模态比例、有效历史长度、有效目标点数、时间偏差分位数，以及按场景统计的 padding 比例。过量日志会增加 I/O；可按确定性抽样记录样本级明细，同时保留完整聚合计数及抽样规则。

## 06 / Forward 产生答案，表示也可以被学出来

模型可以先理解成一个带很多可调整数字的函数：输入当前能获得的信息，输出预测。这里把可调整数字统称为“参数”。Forward 是使用当前参数做一次计算；它并不等同于参数优化。

一种简化的规划链路是：多视角历史图像 → 编码后的特征 → 结合自车状态与导航 → 未来轨迹。特征是模型内部使用的数字表示，不一定对应你人工命名的“锥桶”“车道线”等字段。

**输入、特征、标签、参数是四种不同的东西。** 图像像素或车速是输入；模型中间算出的数字表示是特征；事后记录的专家轨迹是标签；决定这些计算怎样进行的可调数字是参数。特征会随输入改变，参数则由训练更新。只改变一张输入图片，不等于重训模型。

先用同一个极小模型贯穿后面几节：规则是“预测 = 输入 × 权重”。输入为 2、当前权重为 0.2，预测就是 0.4；目标为 1，因此还没答对。**前向计算只算出了 0.4，尚未把 0.2 调好。** 第07节把误差变成 loss，第08节才根据 loss 调权重。这个例子使用无量纲教学数字，不是车辆控制公式。

图里把四类对象分开：输入进入计算，参数决定怎么算，预测是计算结果，目标在训练时用来对答案。

![图解：计算图：输入2乘当前权重0.2得到预测0.4，再与目标1比较得到平方误差0.36，参数尚未更新。](assets/forward-graph.svg)

*无量纲教学模型；前向计算与误差计算不等于参数优化。*

DAVE-2 是容易理解的历史例子：相机图像输入 CNN（从图像中提取表示的卷积神经网络），训练监督为转向相关量，参数通过预测误差更新。它说明中间特征可由最终监督间接学到，不要求每种中间概念都单独标注；这一研究验证的是当时的转向任务，不能当作今天完整城市驾驶能力的证据。[6](#ref-r6)

现代架构也可以保留明确的中间任务。UniAD 将跟踪、地图、运动预测、占用与规划通过 query（传递目标或任务信息的向量）相连，并采用分阶段训练。端到端并不意味着内部只能有一个黑盒或只需一种标签。[7](#ref-r7)

这里的**端到端**强调把从输入到最终任务输出的计算链联系起来学习；哪些模块一起更新，还要看具体训练阶段。中间可以有明确任务和额外监督，不必把每个环节都理解成“没有结构、也无法检查”。

对数据工程师而言，重要的是追踪**字段去向**：图像是否进入视觉分支；导航是否按约定编码；施工标签是过滤条件、采样条件，还是预测目标；哪些标签在当前训练阶段根本不被消费。

需要区分**参数优化**与**其他内部状态变化**：forward、梯度计算和参数更新是不同操作。[2](#ref-r2)

<details class="reading-detail">
<summary>工程补充：为什么前向计算仍可能改变某些状态</summary>

forward 使用当前参数产生预测，通常还没执行基于 loss 的参数优化，但训练模式下的 BatchNorm（批归一化）等模块可能已更新用于归一化的运行统计。这类状态也需要随模型正确保存。因而“还没执行优化器”与“任何内部数字都没变”并非同一个判断。

</details>

## 07 / Loss 是监督信号进入学习的入口

模型输出一条轨迹，专家记录给出另一条轨迹。训练系统需要一个可计算的目标来比较它们。这个目标叫 loss，通常译为损失。最直观的例子是位置误差：预测点离目标点越远，惩罚越大。

**平方误差**就是先相减，再平方：前一节预测 0.4、目标 1，差为 −0.6，平方为 0.36。平方让正负偏差都产生非负惩罚，并让大偏差受到更重惩罚。多个误差求平均，叫**均方误差（MSE）**。loss 是训练希望减小的量；评测指标则是验收时关心的量，两者可以相关，但不必完全相同。

但 loss 只衡量被写进目标的事情。标注了“施工”却没有连接到任何目标、目标点全被 mask、任务权重为零，都会使相应监督失去作用。与此同时，**某项 loss 为零不意味着样本的所有影响都为零**：该输入可能还参与其他任务，batch 统计或正则项也可能产生影响。诊断必须指明哪一项监督、哪一条路径。 [3](#ref-r3)

### 分母错误会制造“训练越来越好”的假象

教学例子：两个样本都 pad 到 3 个未来时刻。把每个有效时刻的二维位置误差先平方求和，得到下面的数值。

例如预测 `(2,0)`、目标 `(1,0)`，这一点的平方位置误差是 $(2-1)^2+(0-0)^2=1$。下表已经完成这一步；表中的 1、4、9 是误差平方后的数值，不是坐标，也不是原始距离。

| 样本 | 第 1 点 | 第 2 点 | 第 3 点 | 有效点数 |
| --- | ---: | ---: | ---: | ---: |
| A | 1 | 4 | 无效 | 2 |
| B | 9 | 无效 | 无效 | 1 |

把表中的有效性直接画出来：实色格进入监督，斜纹格只是占位。再看右侧，分母换了，目标定义也会变。

![图解：有效监督矩阵：A的误差1与4、B的误差9有效，三处占位无效；有效点平均14除3，样本平均5.75。](assets/mask-denominator.svg)

*数值沿用本节教学例子；2.333 对应误用全部 6 个位置作为有效点等权目标的分母。*

如果想让每个**有效时间点**等权，loss 为 $(1+4+9)/3=4.667$。如果想让每个**样本**等权，先对样本内部求均值，再平均，得到 $[(1+4)/2+9]/2=5.75$。二者可以各有用途，必须明确选择。

把无效位置置零，却仍除以固定的 6 个位置，会得到 2.333。padding 越多，loss 可能越小，即使预测没有变好。PyTorch 的默认 MSE `mean` 按所有元素平均；它不会自动知道你心中的有效点分母。[4](#ref-r4)

下面是一种“所有有效时间点等权”的写法。每个时间点先对两个坐标求和，所以其单位为平方米；若要对坐标元素平均，还要相应改变分母，不能拿两个定义的数值直接对比。

先按四步读代码即可：整理有效目标 → 算每个点的平方距离 → 挑出有效点 → 用有效点总数作分母。`sum(dim=-1)` 把最后一轴的 x、y 两项相加，`masked_select(valid)` 只取有效位置。`NaN` 表示非数值；它不会因为乘了零就自动消失。

```python
# pred, target: [B, K, 2]; valid: [B, K], bool
# 在进入这一段前：pred 与有效 target 必须是有限数值。
# 若预测出现 NaN，应排查上游；mask 不能修复非有限预测。
# 无效位置若存 NaN，应先替换；NaN * 0 仍然是 NaN。
safe_target = torch.where(valid[..., None], target, torch.zeros_like(target))
squared_distance = (pred - safe_target).square().sum(dim=-1)
valid_count = valid.sum()
if valid_count == 0:
    # 记录原因；该项监督没有可用目标。是否整步跳过取决于其他loss。
    loss_traj = None
else:
    loss_traj = squared_distance.masked_select(valid).sum() / valid_count
```

实际多任务训练还要确认各项量纲、数值尺度、权重和梯度大小。碰撞惩罚、轨迹误差与舒适性惩罚并不是天然可相加的同一尺度；权重需要配合评测验证，不能只看哪一项标量大。

## 08 / 梯度和优化器分别负责什么

可以把梯度理解成当前 loss 对参数变化的局部敏感度：哪个参数略微增加，会让 loss 上升还是下降。反向传播计算这组敏感度；优化器再按规则调整参数。**`loss.backward()` 主要算梯度，`optimizer.step()` 才执行参数更新。** [2](#ref-r2)

先把“参数更新”看成数轴上一个预测点的移动。灰点是旧预测，竖虚线是目标，蓝点是按当前学习率走一步后的预测。**学习率**就是这一步迈多大。


不用懂整个网络，也能看懂一个教学更新：假设只有一个权重 $w$，模型用输入 $x$ 预测 $wx$。当前 $x=2$、目标为 1、权重为 0.2，预测为 0.4，平方误差为 0.36。局部计算给出的梯度为 −2.4。用学习率 0.1 更新，权重变为 0.44，预测变为 0.88，误差变为 0.0144。

### 不会求导，也能判断这一步往哪走

先试两个相邻权重，输入和目标保持不变：

| 权重 | 预测：权重 × 2 | 平方误差：预测减 1，再平方 |
| ---: | ---: | ---: |
| 0.19 | 0.38 | 0.3844 |
| 0.20 | 0.40 | 0.3600 |
| 0.21 | 0.42 | 0.3364 |

在这个位置，权重略微增大，误差会下降。梯度 −2.4 把这种局部变化趋势表示成一个数；负号说明此处增大权重有利于减小误差。最简单的更新规则是“新权重 = 旧权重 − 学习率 × 梯度”，所以这次增加 $0.1\times2.4=0.24$，得到 $0.2+0.24=0.44$。它只描述当前位置附近的趋势，步子迈得太大仍可能越过合适位置。

把同一个标量例子放到曲线上：横轴是参数，纵轴是训练损失；圆点移动，表示参数确实换了位置。

![图解：平方误差曲线：权重0.2时损失0.36，按梯度负2.4和学习率0.1更新到0.44，损失降至0.0144。](assets/loss-landscape.svg)

*曲线按 L(w)=(2w−1)² 计算，不代表真实驾驶模型的损失地形或泛化收益。*

注意三种“权重”各管一件事：**模型权重**是训练改变的参数；**采样权重**控制样本被抽到的机会；**损失权重**控制某类误差在目标里占多大系数。这里的 0.2 是模型权重，第04节的 249.75 倍和 10 倍则分别属于后两种。

**再想一步**：训练误差下降了，能直接说陌生道路上的驾驶改善了吗？不能，还要检查未用于训练的场景。这个标量例子说明参数如何被误差推动，并不证明模型会开车，也不保证每一步都改善独立评测。过大学习率、噪声或不同样本之间的冲突，都可能使更新不利。

<details class="reading-detail">
<summary>选读：一行梯度推导和一次数值核对</summary>

教学模型与损失为 $\hat y=wx$、$L=(wx-y)^2$。链式法则把“误差怎样随预测变化”和“预测怎样随参数变化”相乘：

$$
\frac{\partial L}{\partial w}=2(wx-y)x,
\qquad w_{\mathrm{new}}=w-\eta\frac{\partial L}{\partial w}.
$$

代入 $x=2,y=1,w=0.2$ 得 $2(0.4-1)\times2=-2.4$，于是 $w_{\mathrm{new}}=0.2-0.1(-2.4)=0.44$。`math_lab.py` 还通过对权重做极小正负扰动的有限差分核对，得到约 −2.39999999993。

真实神经网络有许多层，自动微分沿各条可微路径组合局部导数。上面的单参数例子把这个过程缩小到可以手算的一步。某一分支被 `detach`、放入 `no_grad` 或与 loss 断开时，对应参数就不能通过该路径接收梯度。被冻结的参数也不会像正常可训练参数那样优化。[3](#ref-r3)

</details>

### 有梯度也不一定有有效更新

需要与算法团队一起排查：参数是否在优化器参数组里；学习率是否为零；是否发生非有限梯度；混合精度训练是否跳步；梯度是否在更新前被清零；多个任务梯度是否互相抵消。Adam 等优化器还会使用历史状态，因此不能只看当前一条样本的梯度大小来断言它的净贡献。[13](#ref-r13)、[14](#ref-r14)

即使某条样本的监督进入了已更新的 batch，也只能说明它具备参与该步学习的条件。要判断它是否有用，需要后续的独立对照，而不是在日志中添加一个“学会=true”。

## 09 / 把 Epoch、Step 和 Checkpoint 对齐

| 名词 | 适合怎样理解 | 常见误会 |
| --- | --- | --- |
| sample | 一次取样返回的训练对象 | 一段日志永远只等于一个 sample |
| batch / microbatch | 一次前向或反向使用的一组样本 | 每个 batch 都立刻更新参数 |
| optimizer step | 优化器实际应用一次更新 | 把尝试更新、跳过更新也算作成功更新 |
| epoch | 有限数据集的一轮约定遍历 | 加权有放回采样的一轮保证看过所有样本 |
| checkpoint | 某一时刻保存的模型与相关状态 | 最后一个必然最好，或只存权重就能精确续训 |

数据对账优先看**成功消费次数、去重覆盖、实际更新次数**。epoch 在不同数据流和采样方式中可能采用不同约定，必须写清定义；不能把“跑完一轮”直接当成“每条数据都看过并参与了更新”。

例如单卡 microbatch 为 8，累积 4 个 microbatch 后更新，相当于用 32 次样本暴露形成一次更新。在理想的等大小累积、按目标正确归一化的条件下，多卡全局等效 batch 为“每卡 microbatch × 卡数 × 累积次数”；末尾残缺批次、不同有效点数或不同归一化规则会影响这个等价。分布式 sampler 还可能为对齐各卡长度而补重复索引。[1](#ref-r1)

**梯度累积**是分几小批算梯度，先累加，达到约定数量后再更新一次参数；常用于显存装不下大批次的情况。这里 4 个 microbatch 对应 1 次更新，不是 4 次。日志里的 `step` 有时指读一批，有时指更新一次，因此必须带清楚计数口径。

用点阵数一遍：每组 8 次样本暴露，四组先累积，再执行一次更新。保存 checkpoint 是另一件事。

![图解：梯度累积节奏：四个小批各8次样本暴露，累计32次暴露后执行一次更新；checkpoint按策略保存。](assets/update-rhythm.svg)

*单卡、等大小累积与正确归一化的教学示意；暴露可重复，跳过更新需要单独统计。*

### Checkpoint 也要与数据身份绑定

checkpoint 可以先理解成训练途中的**存档**：保存当时的参数及必要状态，方便选择、评测或续训。模型结构是计算规则的组织方式，参数是其中当前的数字；结构或输入字段顺序不匹配，拿到存档也可能无法正确使用。

推理至少需要匹配的模型结构与参数、特征顺序、预处理、坐标与单位约定。继续训练通常还需优化器、学习率调度、混合精度状态、更新步数；若追求更严格的续跑一致性，还要考虑随机状态、采样器与数据流位置及运行环境。只保存权重，不足以保证中断前后完全相同。[5](#ref-r5)

建议在 checkpoint 的运行元数据中附上代码 commit、配置哈希、manifest 哈希、标签版本、预处理版本和评测协议版本。最后一项尤其有用：同一权重换了指标实现，也可能换一个分数。

评测时 `model.eval()` 切换部分层的行为，`no_grad()` 或 `inference_mode()` 控制梯度记录，职责不同。没有专家标签时模型仍可前向预测；评测时可在模型外使用标签计算指标，不需要据此执行训练更新。[2](#ref-r2)

`eval()` 这个名字容易误导：调用它只是切换到评测模式，不会自动读取测试集或给出分数。你仍要把评测输入交给模型，再按协议计算指标。

## 10 / 先拟合，再泛化，最后看系统结果

训练完成后，先把新增训练样本交给模型回看：连这些样本都没拟合好，就应优先检查训练链。部分团队把这个诊断叫作 `Test on Train`。它回答的是“训练样本是否拟合”，不能回答“面对陌生道路能否正确行动”。

**拟合**是让预测贴近已见样本的目标；**泛化**是对未用于训练的新样本也表现好；**过拟合**则是过度适应训练样本的细节，新样本表现没有相应改善。像只记住练习题答案，不能保证会做换了条件的新题。新城市、天气或采集设备改变了输入的组成与特点，常被称为**分布变化**。

表中的“**通用回归**”是软件测试意义上的回归检查：确认已有能力没有退步。它与“轨迹回归”中预测连续数字的回归任务，虽然中文同名，含义不同。

| 验证层 | 要回答的问题 | 能支持的结论 | 不能据此推出 |
| --- | --- | --- | --- |
| 新增训练样本回看 | 监督是否被模型拟合 | 排查采样、接线、优化等问题 | 已泛化、已安全 |
| 验证集 | 该选哪个配置和 checkpoint | 在验证协议下选择候选模型 | 无偏的最终测试结果 |
| 独立同类测试集 | 新施工场景是否改善 | 在该类独立场景上的表现 | 全部驾驶场景都改善 |
| 通用回归集 | 专项改善是否损伤其他能力 | 已覆盖场景中的退化情况 | 未覆盖风险也不存在 |
| 闭环仿真 | 动作反馈后表现如何 | 在该模拟器和协议下的系统行为 | 真实道路已验证 |

如果测试集被反复用来选采样比例，它实际上也参与了调参，最终结论需要另一份未参与选择的留出集合。专项问题集若来自线上失败，也要说明是否已经被回流训练；相同场景不能一边训练一边当作“独立泛化”证据。

**一个诊断分叉**：训练回看没改善，先查入库、暴露、mask、loss和优化；训练回看改善而独立集不动，再查重复、泄漏、分布差异、任务表达与过拟合。这个分叉是工作假设，具体原因还要证据确认，不能直接把所有失败归咎于“数据不够”。

## 11 / 开环误差与闭环驾驶有什么区别

开环评测通常把记录好的观测交给模型，比较它输出的轨迹与日志中的专家轨迹。预测本身不改变下一条日志输入。

闭环则执行一部分预测，由车辆模型和控制器推进状态，再让模型基于更新后的状态规划。其他交通参与者可以回放原轨迹，也可以根据一定策略反应。这两类闭环不能混称同一种协议。[9](#ref-r9)

先只看有没有回来的箭头：上面预测不改变后续日志，下面动作改变状态，再进入下一次观察。

![图解：开闭环因果图：开环下一帧来自固定日志；闭环动作推进状态后产生新观测，再反馈给策略。](assets/evaluation-loops.svg)

*反馈关系教学示意；闭环结果还依赖车辆模型、控制器与其他交通参与者的行为。*

在这里，**规划器或策略**负责给出接下来怎么走；**控制器**把轨迹转换成转向、加减速等执行量；车辆模型计算执行后车会到哪里。“闭环”闭合的是“观察 → 决策 → 执行 → 新观察”的反馈链。开环日志评测没有把模型这次的动作反馈进下一条输入。

```paper-contrast

```

一个直观例子：模型把车向左偏了 0.3 米。开环下一帧仍来自专家保持正确位置的日志；闭环下一帧对应偏左后的车身位置。模型这时要会纠偏，还要应对新的相对车距。连续几个小偏差，可能把车辆带到训练中很少出现的位置。

行为克隆就是把专家示范当监督。DAgger 研究指出，策略自己的动作会改变后续输入分布；它通过让当前策略产生状态，再为这些状态取得专家动作，聚合到训练数据中，来缓解这个问题。这需要在访问到的新状态上获得有效专家标注，不能把“多收集一遍原来的专家驾驶日志”直接叫作 DAgger。[8](#ref-r8)

对数据生产的启发是：除了收集正常绕行，还可以针对**模型实际失败后的状态**设计受控的纠偏示范或仿真数据。但合成的状态与动作是否物理可行、专家是否知道完整上下文，都需要验证。这是数据设计建议，不是自动部署方案。

### 两个常见轨迹指标

ADE 通常指多个预测时刻位置距离的平均值；FDE 指最后一个预测时刻的位置距离。它们一般以米为单位、越低越好，但不同评测的采样时间、有效点规则和多模态选取方式可能不同。先用一条确定的预测轨迹理解这两个定义。

例如目标点为 `(1,0),(2,0),(3,0)`，预测为 `(1,0),(2,1),(3,2)`，各点距离为 0、1、2 米，因此 ADE=1 米、FDE=2 米。这个值与前面的平方距离 loss 不是同一个量。

一条不走的车可能碰撞少、进度也极差；两条都安全的绕行轨迹也可能与唯一专家轨迹距离不同。应把碰撞、越界、进度与舒适性一起报告，并写清判定阈值和分母。[9](#ref-r9) [12](#ref-r12)

后文的**碰撞代理指标**是按日志或仿真中的几何、时间和判定规则计算的近似评价，用来提示潜在问题；它不直接等于真实道路上的事故概率。**评测协议**就是这套“在哪些场景、怎样运行、怎样计分”的约定。

## 12 / 用三个实验案例理解评测陷阱

下面三个研究案例分别回答：开环分数能否代表闭环表现？低误差是否说明模型用了正确的信息？一个指标改善是否意味着全面改善？设置、结果与解释一并列出。每组只在自身协议内比较，不把不同实验里的同名数字拼成统一排名。

### nuPlan：开环领先不保证闭环领先

在 nuPlan 2024 的一组实验中，同样四种规划器接受了三种评测：固定日志的开环、其他车辆回放日志的闭环、其他车辆按模型反应的闭环。综合得分在 0–1 范围内、越高越好，是协议定义的组合分，**不是“安全率”或“成功概率”**。先把四种规划器看作四个候选方案，在同一列比较高低，再检查它们跨协议的排序是否改变。

| 规划器 | 开环综合分 | 闭环：其他车回放日志 | 闭环：其他车按模型反应 |
| --- | ---: | ---: | ---: |
| Simple Planner | 0.22 | 0.32 | 0.37 |
| IDM Planner | 0.30 | 0.73 | 0.76 |
| Raster Planner | 0.52 | 0.47 | 0.46 |
| UrbanDriver | 0.90 | 0.68 | 0.67 |

比较同一列：UrbanDriver 在开环比 IDM 高 0.60；在可反应闭环中反而低 0.09。这个结果足以反驳“开环排名必然等于闭环排名”。**不同列的得分定义并不完全相同，不能把 0.90→0.67 解读为同一性能下降 23%。** 这组可反应仿真中的其他车辆采用类似 IDM 的行为假设，可能让 IDM 规划器获得协议优势。模拟器自身的设计也会影响排名。[9](#ref-r9)

这个案例说明，评测结果必须和场景组成、控制器、其他车辆的反应规则、评分方法一起保存。改了协议，得分就不能再按同一个量直接比较。

### Ego Status：好分数可能依赖容易的捷径

这里的“自车”指模型正在控制的这辆车。L2 位置误差先理解为预测位置与参考位置的直线距离；多时刻如何汇总由协议决定。CCR 在此指路沿碰撞指标，用来检查预测轨迹是否与路沿冲突。模型名称只是候选方案的名字，第一遍可以先看“用了什么输入、测了什么、能推出什么”。

Ego Status 研究比较了不同输入下的规划结果。仅用自车状态与驾驶指令的 Ego-MLP，平均 L2 位置误差为 0.35 米、平均碰撞代理率为 0.37%；另一方案 BEV-Planner++ 的两个数值为 0.35 米和 0.34%。但两者的路沿碰撞指标 CCR 分别为 2.93% 和 3.16%。这些是 nuScenes 开环协议内的时间点汇总，不是实车碰撞率。这组评测只保留具备完整未来真值轨迹的5,119个验证样本，约占筛选前6,019个样本的85%；改变有效样本筛选会改变比较范围。

它说明：某些日志评测可以让依赖自车状态的简单模型得到很有竞争力的分数。不能从这些分数推出“不需要视觉就能开车”。可以进一步做两类诊断：把图像屏蔽后重新评测，检查分数是否仍能维持；改变输入速度，观察预测如何变化。它们帮助定位模型对输入的依赖。单一的路沿碰撞指标 CCR 也有局限：如果预测轨迹接近静止，它可能看起来很好，却未必完成驾驶任务。[10](#ref-r10)

对数据工程的直接要求：记录速度、导航和输入来源；按直行、转弯、停车等场景拆分评测；参与设计屏蔽与扰动诊断。屏蔽后表现如何，是特定实验的证据，不是对内部“理解”能力的直接证明。

### UniAD：安全代理指标与贴近专家轨迹可能有取舍

UniAD 的一组规划消融比较了是否在推理时加入占用优化：利用预测出的空间占用信息，调整规划轨迹以减少潜在碰撞。加入这一步后，3 秒位置误差从 1.76 米变为 1.81 米，同时 3 秒碰撞代理率从 1.39% 变为 1.05%，下降 0.34 个百分点。这里更低的碰撞代理与略高的轨迹误差同时出现，不应只挑一个指标宣布全面改善。[7](#ref-r7)

**消融实验**是有意关掉、移除或替换一个环节，再观察结果怎样变化，用来判断该环节在指定设置中的作用。“占用”表示哪些空间可能被车辆或障碍物占据；上述优化是在已经给出的轨迹上再作调整。

该优化发生在推理阶段，用预测占用约束调整轨迹。系统收益可能来自后处理或控制变化，不能把整套系统变好自动归因于新增训练数据。这组实验与前面的 Ego Status 案例采用不同评测协议，碰撞数值不能直接横向比较。

## 13 / 为什么难样本值得追踪，却不能直接删掉

一种数据诊断思路叫 **Dataset Cartography（数据地图）**：观察同一条样本在训练过程中的变化，而不只看训练结束时的一次误差。在最初的 NLP 分类研究中，研究者记录模型在多个训练阶段给正确类别的概率，用平均值表示信心，用波动描述训练动态。它研究的是语言分类，不能直接当作已验证的驾驶轨迹回归方法。[11](#ref-r11)

直观上，始终高信心的样本可能较容易；反复摇摆的样本可能位于模型的边界；始终低信心的样本可能包含标注问题，也可能是真的困难、缺少上下文或模型能力不足。**“难学”不能直接等于“坏数据”。**

**分类**是从若干类别里选答案，比如把一句话归到正确类别；**回归**是预测连续数字，比如未来位置。分类模型给正确类别的概率，可以用于观察它的信心；轨迹误差以米等单位表示，不能直接套用同一个概率解释。这里的 NLP 指自然语言处理。

一组实验先在语言分类数据集 WinoGrande 中选训练样本，再用另一个数据集 WSC 检查迁移表现：选取训练中波动最高的 33% 样本时，WSC 准确率为 87.6%；随机选 33% 时为 85.6%，相差 2.0 个百分点，均为 3 个随机种子的均值。其他分析还发现，只保留极小的困难子集可能使优化失败，容易样本仍有作用。该观察来自特定 NLP 设置，不证明自动驾驶也有同样提升。[11](#ref-r11)

**随机种子**控制伪随机过程的起点，例如初始化、打乱和抽样；固定它便于在兼容环境中复查同一次实验。换种子重跑，是检查结果是否过度依赖某一次随机过程，不能把一个种子下的好结果当成稳定规律。

若把这个思路用于轨迹回归，可以先记录每条场景的有效点数、回归误差与跨 checkpoint 的变化，再人工回看高误差、波动大或持续退化的样本。**这是可尝试的迁移诊断方案，驾驶任务上的有效性仍需单独实验验证。** 回归误差也不应被直接命名为分类置信度。

一个有价值的数据回看表，可以包含 `sample_id / scenario / exposure_count / valid_targets / error_at_ckpt_A / error_at_ckpt_B / reviewed_reason`。最终动作应有证据：修标签、补上下文、降低重复、添加相邻困难状态，或保留为合理的困难样本；不要只按 loss 高低自动清理。

## 14 / 真正的数据收益实验怎样设计

如果新数据、采样比例、模型结构、训练时长和评测脚本一起变了，即使分数上升，也无法分离新增数据的作用。下面给出一个可操作的实验设计建议。

**基线**就是比较的起点；**对照**尽量让其他条件一致，只改变要研究的因素。比如 B 对 A 主要看加入数据，C 对 B 再看调采样。若每组同时换了网络和训练时长，就难以回答“究竟哪一步带来变化”。

把对照关系横向摆开：B 对 A 增加数据，C 对 B 改变暴露；右侧的更新预算保持同一口径。

![图解：实验对照矩阵：A原始数据，B增加数据，C在B的数据上改变采样；实际更新预算保持一致。](assets/controlled-trial.svg)

*实验设计示意，点与短条只表示组成，不表示真实条数或步数；没有绘制未经测量的收益。*

| 实验 | 数据与采样 | 训练预算 | 可以回答的问题 |
| --- | --- | --- | --- |
| A 基线 | 原始清单与策略 | 固定实际更新步数 | 当前起点 |
| B 新增数据 | 新清单，尽量保持其他设置 | 与 A 相同 | 固定预算下加入数据的综合效果 |
| C 新增并调采样 | 同 B，改变新增场景暴露 | 与 A 相同 | 暴露策略是否改变收益与代价 |
| D 预算对照 | 原始清单，多训练 | 与另一个扩预算实验匹配 | 收益是否主要来自更多更新或算力 |

固定 step 并不同时保证每条数据看过相同次数；固定 epoch 也不保证更新预算相同。应报告总抽取次数、去重覆盖、每类暴露和实际更新次数。必要时分别做预算匹配与暴露匹配实验，承认它们回答的问题不同。

同一批评测场景应成对运行旧模型与新模型。若有资源，使用多个训练随机种子，区分训练随机性与评测抽样波动。**置信区间**是按统计方法给出的估计范围，用来表达有限样本带来的不确定性。计算时宜按独立 scene 或 drive 重采样，不能把一段视频的 1,000 个相邻帧当成 1,000 个独立事件。

一个教学读数：旧模型在 200 个独立施工场景失败 20 次，新模型失败 12 次，失败率从 10% 到 6%，下降 **4 个百分点**，相对下降 40%。但仅有这两个总数不足以判断配对显著性，还要知道哪些场景由败变胜、由胜变败，以及场景是否真正独立。

4 个百分点来自 $10\%-6\%$；相对下降 40% 来自 $(20-12)/20$。**配对**表示新旧模型做同一组场景，逐场比较；**不确定性**提醒我们，换一批场景或一次训练，结果可能波动。这里所说的显著性，是相对于随机波动有多强的统计证据，不等于“肉眼看起来差得多”。

另一个边界：测了 100 次都没失败，也可能只是还没碰到罕见情况，不能宣布真实失败概率为零。更多独立、可比的试验能缩小这类不确定性；重复播放同一段场景并不自动增加同等数量的独立证据。

<details class="reading-detail">
<summary>选读：零失败时，统计上界是什么意思</summary>

在独立同分布的二项模型下，100 次试验零失败，95% 单侧置信上界约为 2.95%；1,000 次零失败，上界仍约为 0.30%。95% 描述这类区间构造方法在重复试验中的覆盖性质，不是道路安全保证，也不是“事故概率有 95% 的可能为零”。这是理想统计教学例子，不是道路安全认证方法。其中 $n$ 是相互独立、条件相同的试验次数，上界为 $1-0.05^{1/n}$，已由 `math_lab.py` 核验。

</details>

## 15 / 给数据团队的一张诊断表

遇到“模型没效果”，先把现象对应到证据，再决定下一步。下面每一行都是待验证假设，不能只凭表面现象自动归因。

| 观察到的现象 | 先看哪份证据 | 常见下一步 |
| --- | --- | --- |
| 交付了，但清单里没有 | 交付ID与训练manifest的差集 | 查版本登记、配置引用、过滤回执 |
| 清单有，但读取很少 | 按场景的采样与消费计数 | 查权重、固定步数、流分片、重复和丢弃 |
| 读到了，但目标全无效 | 有效标签数和mask分布 | 查时间窗、缺帧、坐标、标签版本与collate |
| 有loss，目标分支没梯度 | 参数组、梯度路径与冻结配置 | 与算法团队查detach、no_grad、未接线分支 |
| backward正常，权重未变 | 实际更新计数、学习率、跳步日志 | 查累积边界、溢出、参数组与恢复状态 |
| 训练回看好，独立集不动 | 场景重复、split、分场景误差 | 查过拟合、泄漏、分布差异和任务缺项 |
| 轨迹误差好，闭环变差 | 碰撞、越界、进度、控制与代理版本 | 查纠偏能力、后处理、动力学与交互 |
| 专项好，普通场景退化 | 通用回归与每类暴露 | 调整目标取舍，验证采样和loss叠加 |

回执可以贯穿 `delivery_id → sample_id → manifest_hash → run_id → optimizer_update → checkpoint_id → evaluation_protocol`。这条身份链让两边讨论同一次训练与同一份数据，而不是各自拿一张正确但互不对应的截图。

不要尝试在生产大模型上永久记录每个参数的每样本梯度。成本可能很高，而且梯度范数也不是收益本身。先保证低成本的数量对账、有效目标与运行身份，针对代表性 batch 做更深入诊断。

### 实验 C：选做一个真正的训练循环

`labs/torch_lab.py` 用一个简单线性模型学习已知规则：输出 = −0.5 × 横向误差 + 1.5 × 施工标记。**横向误差和施工标记已直接作为输入提供**，所以不涉及相机感知、轨迹规划或真实驾驶。

训练集 1,024 条，其中 16 条施工样本；独立生成验证集和测试集各 400 条，各含 200 条施工样本，用于看清两类误差。两个实验都用 batch=32、120 次更新、学习率=0.05：一组均匀有放回采样，另一组给施工样本 21 倍权重，使其目标抽样比例变为 25%。只在验证集上选 checkpoint，然后各评测测试集一次。

```bash
uv run --no-project --python 3.13 --with torch==2.15.0 --with numpy==2.5.4 \
  labs/torch_lab.py --out labs/runs/my-torch-run
```

核心循环如下，完整代码还记录暴露、保存模型并验证重载前后预测一致。

读循环时只需抓住五步：`zero_grad` 清掉上一轮梯度 → `model` 用当前参数预测 → `mse_loss` 对答案 → `backward` 算梯度 → `step` 调参数。梯度默认会累加，所以这里每批开始先清零；要做第09节的梯度累积时，清零位置和更新节奏需要相应改变。

```python
for observation, expert_target, is_construction in loader:
    optimizer.zero_grad(set_to_none=True)
    predicted = model(observation)
    loss = torch.nn.functional.mse_loss(predicted, expert_target)
    loss.backward()
    optimizer.step()
```

这段实验的用途是把“抽样 → loss → 更新 → 分组评测”串起来。它不应被用来证明“长尾一律过采样到25%最好”，也不能拿平衡测试集的整体 MSE 当作真实道路平均风险。应查看各类结果、分母和适用分布。

**一次已运行的教学结果**（Python 3.13.14、PyTorch 2.15.0、CPU、单个随机种子7）：

| 采样方案 | 总抽取次数 | 施工抽取次数 | 去重训练样本 | 普通类测试MSE | 施工类测试MSE |
| --- | ---: | ---: | ---: | ---: | ---: |
| 均匀采样 | 3,840 | 78 | 1006 | 0.000527 | 1.335434 |
| 施工21倍权重 | 3,840 | 978 | 978 | 0.003187 | 0.011992 |

两组均在第120次更新取得这次运行中的最优验证目标。这次运行中，加权采样的施工类测试误差从1.335434降至0.011992，同时普通类误差从约0.000527变为0.003187，去重覆盖从1,006降到978。这里暴露增加主要来自重复抽取，不能据此称为数据多样性提升。MSE单位为教学归一化动作的平方，每类测试分母均为200个独立生成样本；本结果仅是一组可复核演示，没有多随机种子统计结论。

程序另行验证了两个保存模型重载后的预测逐元素一致；完整数值与验证集选模轨迹保存在 `labs/runs/torch-verified-20261103/torch-results.json`。

第一次运行可先检查四个信号：实验 A 是否得到 5→4→3→2→1；实验 B 的默认更新 loss 是否为 0.0144；实验 C 两组是否都抽取 3,840 次；加权组是否在提高施工暴露的同时改变普通类误差。数值不一致时，先核对依赖版本与数据改动，再判断是否发现模型机制问题。`--out` 是输出目录参数；重复运行请换一个不存在的目录。
